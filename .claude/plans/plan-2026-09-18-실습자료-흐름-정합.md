# 계획 · 발표자료를 실제 실습자료 흐름에 맞추기 (2026-09-18)

대상: `topics/sk-hynix-ai-agent-guide-edu/` (덱 v0.5, 55장) · 도구: 서브에이전트 `llm-edu-designer`
상세 방향과 확정 사실표는 `topics/sk-hynix-ai-agent-guide-edu/ROADMAP2.md`에 있다. 이 파일은 그 요약본이다.

## 1. 왜 하는가

- 현재 덱은 사용자가 **말로 전해 준** 실습 흐름에 맞춰져 있다(ROADMAP1).
- 실제 실습자료 화면을 전사한 `docs/ai-agent-guide-실습자료-강의흐름요약.md`(요약본)가 들어왔고, 덱과 여러 곳이 다르다.
- 서브에이전트 `llm-edu-designer`로 세 가지를 받는다: **① 스토리라인 ② 내용의 짜임새 검수 ③ 슬라이드마다 배치될 내용과 콘티.**

## 2. 찾아낸 것

### 서브에이전트 정의서의 낡은 전제 (보정함)

- 슬라이드 v0.3 52장 · 콘티 v0.4 57장 → 실제는 v0.5 55장
- 7블록 B1–B7 · 시간표 → 구간 코드와 시간은 화면 금지, 뼈대는 실습 9개
- 원본 html · 실습 코드가 저장소에 있다고 전제 → 둘 다 없음(요약본이 유일한 근거)
- "요약본에 있는 내부 URL·테이블명은 써도 된다" → 하우스 룰과 충돌, 역할 이름으로
- 씬 ID `B2-N01` → `N01…`, 안내판은 `LAB01…LAB08`(`LAB04b`)

### 덱 ↔ 요약본 차이 (요지)

| 실습 | 고칠 것 |
|---|---|
| 01 환경 | 열쇠 3종 · `.env` · uv · 당일 범위 |
| 02 단일호출 | PromptTemplate와 체인, "아메리카노" 관찰 |
| 03 캐릭터봇 | 관찰 3종(temperature · 페르소나 · format)으로 재작성 |
| 04 RAG | "본문 통째 요약" 5곳 → 검색 → 근거 → 답변 흐름 + "조각 2~4개" 관찰 |
| 04b Tool | "인자 없는 도구" 4곳 → 계산 도구 3종, 0 나누기, 401 |
| 05 Agent | "Workflow에 가깝다" → Agent 루프 · 반복 상한 · 안전장치 |
| 06 설치 | "오후는 별개 경로" 4곳 → 같은 플랫폼 · 같은 키, settings.json |
| 07 활용 | 기본 프롬프트 3종, 공식 문서 습관 (세 방향은 유지) |
| 08 자유실습 | 구현 방식 선택, 서사 축 되짚기 |

## 3. 사용자 확정 사항 (ROADMAP2 0절의 요약)

| 번호 | 확정 |
|---|---|
| R2-1 | 기준은 요약본. 원본 html · 실습 코드는 저장소에 없음 |
| R2-2 | RAG는 요약본 흐름대로 + "기사 한 편은 조각 2~4개라 검색이 거의 전부를 가져온다" 관찰. k 값은 화면에서 단정하지 않음 |
| R2-3 | Tool · Agent는 요약본대로(계산 도구 3종 → 설비 ID 인자 조회 도구 → Agent 루프) |
| R2-4 | 긍정봇 관찰은 temperature · 페르소나 · format 지정. few-shot 비교 · 기억 관찰 · 인젝션은 다루지 않음 |
| R2-5 | LLM 호출 키는 오전 · 오후 같은 계열, 임베딩 키는 별도, DataLake JWT는 다른 플랫폼 |
| R2-6 | 프로그램 설치만 사전 과제, 키 · `.env` · uv sync · 검증 · settings.json은 당일 |
| R2-7 | 실습 번호를 실습자료와 동일하게(01~08 · 04b), 파일명은 화면에 쓰지 않음 |
| R2-8 | 두뇌 · 책 · 손발 · 조종 · 내 PC의 에이전트 비유를 서사 축으로 |
| R2-9 | 본문 50장 안팎 |
| R2-10 | 실습 03의 Streamlit은 실행만, 세 층 설명은 실습 05 앞 |
| R2-11 | '장비 메모리' 사이드바는 [확인 필요] → 사내 Claude 확인 요청서 |
| R2-12 | ROADMAP1 결정 1 · 2 · 8, 부록, 오후 세 방향, 하우스 룰은 유지 |

조각 수 검증: 약 2,000자 기사 → chunk 1000 / overlap 150에서 3개(추출 방식에 따라 4개). 2개가 되려면 약 1,850자 이하.

## 4. 진행 단계

| Phase | 내용 | 산출물 |
|---|---|---|
| 0 | 사실 확정 (완료) | `ROADMAP2.md` 0절 |
| 1 | 정의서 보정 · 에이전트 등록 문서 · `llm-professional` 전제 수정 · 사내 확인 요청서 | `.claude/agents/llm-edu-designer.md`, `.codex/agents/llm-edu-designer.toml`, AGENTS.md 등, `docs/handoff-inhouse-claude-lab-check.md` |
| 2 | 서브에이전트 실행: ① review → ② storyboard → ③ conti | `docs/edu-review-v1-…md`, `docs/edu-storyboard-v1-…md`, `docs/edu-conti-v1-…md` |
| 3 | 교차 검수(`llm-professional`, `lecture_expert`) → 콘티 반영 | `_workspace/roadmap2/` |

이번 범위는 Phase 0~2(가능하면 3)의 md 산출물까지다. `index.html`은 건드리지 않는다.

## 5. 끝났는지 확인하는 방법

1. `python scripts\validate_codex_port.py` 통과
2. 산출물 세 가지가 `docs/`에 있고 각 문서 말미에 「확인 필요 사항」이 있음
3. 산출물 문안에 시각·분 · 구간 코드 · 사내 고유명 · 반말 · 확정 사실과 충돌하는 문장이 없음
4. 스토리보드 본문 50장 안팎, 실습 안내판이 실습자료 번호와 일대일 대응
