## 문제 분석

에이전트가 여러 개 동시에 돌다가 사용 한도에 걸리면 한꺼번에 멈춘다. 멈춘 뒤에는 어느 단계·어느 장면까지 끝났는지 파일로 알 수 있어야 이어서 진행할 수 있다.

## 설계

단계는 차수 묶음(B1 / B2+B3 / B4+B5 / B6+B7 / 부록)마다 같은 순서로 돈다.

```text
문구(slide_copy) → UI 배치(slide_ui) → 강사 사전 검토(lecture_review/<묶음>-v0.4-pre.md)
  → 빌드(빌더가 BLOCK 조각 작성 → 검사 → index.html에 조립) → sync_overview.py --renumber
  → validate·lint·--check·Playwright 넘침 검사 → 강사 사후 검토(<묶음>-v0.4-post.md)
→ T8 전체 QA → T9 문서 동기화 → 마지막 검토(Playwright, 시각·내용)
```

- 에이전트는 장면 하나를 끝낼 때마다 파일에 바로 저장한다. 진행 위치는 파일의 `## <장면ID> · <제목> (v0.4)` 제목으로 확인한다.
- 단계가 끝날 때마다 커밋해 세이브 포인트를 남긴다.

```bash

grep -n '^## .*(v0.4' _workspace/slide_copy/*.md
# 배치 진행 위치
```

- 빌드 보조 도구(세션 scratchpad, 저장소 밖): `splice_blocks.py`(BLOCK 조각을 index.html에 끼움, `--extract`로 현재 BLOCK 추출), `check_fragment.py`(조각 규칙 검사: 장면 ID 순서, data-skill, 필수 요소, 인라인 style·br·hex·외부 이미지·현업가이드 파일명·CSS에 없는 클래스·data-editable 누락). 새 세션에서는 이 설명대로 다시 만든다.
- 빌더 공통 지침(세션 scratchpad `builder_brief.md`): 빌더는 `index.html`에 직접 쓰지 않고 `scratchpad/blocks/<NAME>.html` 조각을 장면마다 덧붙여 저장한다. 문구는 slide_copy v0.4 절, 구조는 slide_ui v0.4 배치 절을 따른다. `check_fragment.py` 통과 후 오케스트레이터가 `splice_blocks.py`로 조립한다.
- 부록 확인 결과(2026-09-16): A07–A10 API 이름은 Context7 공식 문서와 일치. A10은 승인 카드만 자른 `assets/img/appendix/cowork-hitl-approval-card.png`를 쓴다.
