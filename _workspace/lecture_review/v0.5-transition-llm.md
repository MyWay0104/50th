검토 기준: `_workspace/roadmap1/add_transition_spec.md`, `ROADMAP1.md` 0절 결정 3·7, 앞뒤 장면 S08·S09·S14·S15·S17·S29·S20·S21 화면·노트(`review_r3/deck_text_t.md` 9~11, 16~19, 22~26쪽).

## 총평

- 세 장 모두 "① 지금 되는 것"이 직전 실습의 소단계와 1:1로 맞고(S08 ②③④⑤ → T01, S13 ①③④ → T02, S19 ③④ → T03), 결정 3(본문 전체 요약, 검색 조각 관찰 없음)·결정 7(도구 인자 없음, 부를지만 정함)을 어기는 문구는 없다.
- "왜 다음 단계인가" 논리는 원론상 맞다. RAG 한계 = 문서에 없는 집계·현재 상태·행동, 도구 한계 = 코드 실행자만 쓸 수 있음 → 화면. 도구 호출 원론(모델은 요청, 코드가 실행)도 정확하다.
- T02 띠 "도구가 붙어야 Agent로 갈 수 있습니다"는 S17의 Agent 정의(모델이 다음 행동을 고르며 LLM ⇄ 도구 반복)와 충돌하지 않는다. 도구를 필요조건으로만 말하고 충분조건으로 말하지 않으며, S17이 실습 3을 "Workflow에 가깝다"고 판정하는 것과도 양립한다. **통과.**
- 남은 문제는 세 가지 중간 사항이다. (1) T02에 `@tool`이 S16보다 먼저 화면에 나와 새 용어 0 원칙 위반, (2) T02 ② "정확한 건수·집계"와 ③ "정해진 쿼리로 테이블 조회"(실습 3은 상태 조회, 집계 없음)의 결핍→해결 짝이 느슨함, (3) T03 ② "결과 없음 같은 안내"는 실습 4가 채우지 않고 오후 선택 과제(M01)가 채우는데 노트가 실습 4가 채우는 것처럼 읽힘.
- "다음 장" 참조(S08→T01→S09, S14→T02→S15, S17→T03→S29)는 모두 맞다.

## 항목별 확인 결과

- (a) 사실 일치: T01 ①③, T02 ①, T03 ①③ 모두 직전·다음 실습 소단계와 일치. 결정 3 위반 없음(T01·T02 어디에도 "조각을 골라 넘김"·"검색 조각" 표현 없음, "본문을 붙여" 일관). 결정 7 위반 없음(T02 ③ "부를지는 모델, 실행은 코드", T03 ① "도구가 필요한 질문 구분"). 불일치는 위 표의 T02 건수 집계·T03 결과 없음 안내 두 건뿐.
- (b) 원론: 환각(근거 없이 그럴듯함), RAG는 이번 답변에만 자료 사용, 도구 호출은 모델 요청·프로그램 실행, 화면은 코드 비사용자를 위한 층 — 모두 맞음. "모델은 숫자를 세지 않는다"만 과장.
- (c) 새 용어: T01 없음(환각은 S08 칩 기출). T02 `@tool`·`쿼리` 첫 등장(위 표). T03 없음(Streamlit·장비 ID·Claude Code 모두 G01·S02 기출). "다음 장" 참조 6곳 모두 맞음. 중복은 T01 ② ↔ S09 상단 세 상자(의도된 반복이나 노트 도입부까지 같음, 위 표 S09 행).
- (d) T02 띠 ↔ S17: 충돌 없음. 띠는 "도구가 있어야 갈 수 있다"(필요조건), S17은 "도구 + 모델이 다음 행동 선택"(정의)이고 실습 3을 Workflow에 가깝다고 판정. T02 노트가 "Agent 정의는 다음 구간 장에서"라고 예고하므로 순서도 맞음. Anthropic "Building effective agents"의 정의(모델이 도구 사용을 스스로 지휘)와도 일치.
