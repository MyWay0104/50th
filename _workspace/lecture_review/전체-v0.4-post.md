# 전체 덱 v0.4 최종 내용 검토 (post-build, 57장)

- 검토 대상: index.html에서 추출한 57장 화면 글자·발표자 노트, 서사 설계(slide-plan-v0.4 2절·11-2절), 확인용 스크린샷 24쪽·57쪽
- 검토 관점: 하루 전체 흐름(기승전결)과 사실. 차수별 시간 배분·인지 부하는 차수 검토에서 끝났으므로 다시 채점하지 않음

## 전체 판정

- **기(B1)**: S01 질문 → 토큰·Attention·서버·temperature → S08 "최신 자료 질문의 한계를 10시에 가져간다"로 끝나고, S09가 그 답을 되묻는 것으로 시작한다. 이음매가 가장 매끄럽다.
- **승(B2·B3)**: 근거 부족(S09) → RAG → 검색과 답변을 나눠 보기(S14) → "정확한 조회는 도구로"(S14→S15) → Tool·Workflow·Part Finder → S21 "이 앱이 13:20 작업 대상"까지 인과가 한 줄로 이어진다. 다만 오전 앱 구조를 부르는 층 이름이 S21(모델·도구)과 S24·S29(처리·데이터)에서 달라, 검색이 어느 층인지가 흔들린다.
- **전(B4·B5)**: S22 태그 줄에 역할 반전 문장이 화면에 드러나고, "모델은 요청하고 프로그램이 실행한다"(S16)가 Claude Code(S21·S22)로 이어진다. 요청문 6칸(S25)이 S32·S40에서 재사용된다. 흠은 두 가지다. 명령 승인 안내가 S32에 처음 나오는데 실제 승인 요청은 S26 Python 실행 때 먼저 뜬다. 또 오전 앱에 이미 있는 "근거 표시"(S20 ④)를 오후 개선 과제로 제시한다.
- **결(B6·B7)**: 수집 누락(S11→S35), 근거 문장 찾기(S13→S38), 요청문 6칸(S25→S40), 탐색·계획(S28→S41)이 모두 오전·오후를 되부르며 닫혀, 서사가 가장 촘촘하다.
- **G02**: 중심 메시지와 4가지 성과는 닫지만, G01의 네 막(만나다→연결하다→뒤집다→남기다)은 화면에도 노트에도 다시 나오지 않는다. G00의 네 단계와 G02의 네 성과가 둘 다 "네 가지"라 섞일 여지도 있다. 노트의 "일곱 번 반복"은 근거가 없다.
- **사실 오류**: 1건. S12 노트가 Deep Agents를 "더 세밀한 흐름 제어" 쪽에 둬서, 부록 A03·A09의 "기능을 미리 묶은 하네스"와 반대로 설명한다. 조사정리 11-2의 금지 표현 16개는 본문·노트에 남아 있지 않다.
- **보안·목적**: 사내 데이터 외부 전송(S23), 권한 우회(S26 "사내 가이드 밖 방법 말고"), 되돌리기 어려운 작업 제외(S39·S41)가 일관되게 안내된다. 비전공자를 겁주거나 "AI가 다 해 준다"는 식의 문구는 없다.
