## 총평

- 10건 중 해결 8·변형 수용 1(S21 Context)·부분 해결 1(S10 흐름 상자). 결정 기록 8개(시간표 G01만, 선택 과제, 본문 통째 요약, 사전 설치, 긍정봇 few-shot, 싱글턴, 도구 인자 없음, Part Finder 배치)는 모두 지켜졌다.
- 원론 문장을 50장 전부 다시 읽은 결과 **개념 오류(높음)는 없다.** 토큰·자기회귀·컨텍스트 윈도우·temperature·메시지 역할·few-shot·환각·인덱싱/검색 두 시점·청킹·임베딩·벡터 검색·tool_calls/ToolMessage·루프 종료 조건·Workflow 5패턴·풀스택 세 층·Coding Agent 루프·CLAUDE.md 비보안·MCP 3종(도구·자료·프롬프트)·Hook 2유형·State/Node/Edge·grade→rewrite·interrupt/Command·미들웨어 위치 모두 교안·공식 문서 기준과 맞다.
- 반영으로 새로 생긴 불일치는 1건: S21 노트에 들어간 "Memory 자리를 지침 파일과 작업 기록으로 채운다"가 C04 "CLAUDE.md = Context"와 어긋난다(중간).
- 실습 직전 새 용어 수(S04 3·L01 3·S10+R01 3(흐름 상자 제외)·S16 3·S29 1·S22 1·S30 2·C04 1)와 개념 칩 짝(실습 1~5·선택 과제·자유 실습)은 모두 한도 안이고, 관찰 포인트(content+토큰, system 한 줄, temperature 3회, 조각 수·chunk_size, 근거 대조, 없으면 없음, tool_calls 빔, 연결 짚기, 파일 대조, 바뀐 줄·실행 결과)도 그대로 살아 있다.
- 오전→오후 연결은 S21 "오전엔 내가 도구를 붙였고, 오후엔 도구가 이미 붙은 Agent인 Claude Code에게" → S22 "한 바퀴가 여러 바퀴로" → C04 하네스 세 요소 대응으로 이어지며, 하네스·Skill·MCP·HITL은 본문 한 줄+부록 구조로 필요한 만큼만 있다.
