출처: Claude Code 공식 문서 Best practices · Permissions

이 과제는 자유 주제가 아직 정해지지 않은 분을 위한 선택 과제로 강제가 아니며, 앞에서 적은 완료 조건 한 문장이 이 과제와 같으면 그대로 요청문으로 쓰고, 다른 기능을 적었다면 화면의 완료 조건을 씁니다. 먼저 Claude Code에게 오전 챗봇의 구조와 수정할 위치를 설명하게 하는데, 첫 번째 칩처럼 실습 5에서 한 읽기와 같은 단계입니다. 다음으로 바꿀 곳과 완료 조건을 담은 계획을 받아 우리가 읽고 확인하고, 이어서 계획한 범위만 구현하게 하며, 전체 앱을 다시 짜거나 기능을 여러 개 붙이는 것은 범위에 넣지 않습니다. 마지막 검증에서는 실행 전에 결과를 먼저 예측해 말하고 나서, 없는 장비 ID와 오전에 정상 동작하던 질문을 둘 다 실행하며, 옆 사람이 골라 준 다른 입력으로 한 번 더 확인합니다. 오른쪽 승인 요청 카드는 요청 화면의 모양을 일반화한 개념 예시로, Claude Code가 이런 식으로 파일 수정이나 명령 실행 승인을 요청하면 무엇을 하려는지 읽고 나서 승인하고, 모르겠으면 아니오를 고른 뒤 손을 들어 주세요. 부록의 HITL, 곧 사람이 작업 흐름 중간에서 승인하는 방식을 직접 겪는 장면이고, 공식 문서 Permissions도 이런 승인 범위를 설정으로 정하는 방법을 설명합니다. 완료했다는 말이 아니라 바뀐 줄과 실행 결과로 판단하고, 확인하지 못한 입력은 미확인으로 적어 두면 됩니다.
