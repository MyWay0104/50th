부록 · LangGraph 흐름 설계

분기·중단·재개가 필요할 때 흐름을 그래프로 직접 그립니다.

LangGraph는 상태(State)·노드(Node, 처리 단계)·연결(Edge)로 흐름을 정의합니다. create_agent의 도구 호출 루프도 내부는 그래프입니다. 순서가 고정된 작업이면 직접 그리지 않아도 됩니다.

State · messages · category를 모든 노드가 공유
START →
분류classify 노드
조건부 Edge: 질문 종류로 다음 노드 선택 ↓
기사 검색
SQL 조회
바로 답변

모두 END로 · 개념 예시, 오전 앱 구조 아님

StateGraph 빌드 · 교육용 축약(일부 줄 생략)
g = StateGraph(State)
g.add_node("classify", classify)
g.add_edge(START, "classify")
g.add_conditional_edges("classify", route)
app = g.compile(checkpointer=...)
app.invoke({"messages": [...]}, config)

출처: LangGraph Overview

오전에 LangChain으로 모델과 검색을 연결했다면, LangGraph는 코드 안에 숨어 있던 흐름을 눈에 보이는 그래프로 밖으로 꺼내는 도구입니다. 화면 왼쪽 그림처럼 모든 노드가 같은 State를 읽고 일부를 갱신하며, 분류 노드 뒤의 조건부 Edge가 질문 종류에 따라 다음 노드를 고릅니다. 분기 예시는 오전에 본 기사 검색과 SQL 조회를 빌려 온 것일 뿐, 오전 앱이 이렇게 만들어졌다는 뜻은 아닙니다. create_agent가 만드는 도구 호출 루프도 안을 보면 모델 노드와 도구 노드가 조건부 Edge로 오가는 그래프입니다. 오른쪽 코드는 그래프를 만들고, 노드를 붙이고, Edge로 잇고, compile한 뒤 실행하는 순서를 교육용으로 줄인 것이고, 체크포인터를 붙이면 중단한 지점에서 이어갈 수 있습니다. 순차 연결, 라우팅, 병렬, 오케스트레이터-워커, 평가-개선 같은 워크플로 패턴도 모두 이 세 요소로 그릴 수 있고, 되돌아가는 루프에는 반드시 멈추는 조건을 둡니다. 순서가 고정된 작업이라면 함수 호출만으로도 충분하니, 분기·중단·재개가 정말 필요한지부터 확인하세요.
