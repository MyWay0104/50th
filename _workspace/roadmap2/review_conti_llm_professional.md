## 총평

콘티는 R2-1~R2-21을 충실히 반영했고, 옛 흐름의 충돌 문장(통째로 · 인자 없음 · 별개 경로 · 긍정봇 기억 · few-shot · 챗봇 · 실습 가이드 해당 장)은 화면과 노트에서 모두 걷혔다. 전환 논리(두뇌 → 책 → 손발 → 조종 → 내 PC의 에이전트 → 적용)는 T01 · T02 · T03 · S21 · S22 · G02에서 같은 고정 문장으로 이어지고, 0으로 나누기와 401의 예고 → 디브리핑 구조는 세 교안보다도 낫다.

**R2-14("실습 04b의 손으로 돌린 반복이 Agent 루프의 가장 작은 모양")는 원론상 무리가 없다.** 4일 교안 p137이 ReAct Agent를 "Tool-calling 루프"로 정의하고 끝나는 조건을 "tool_calls 있으면 Tool로, 없으면 END"로 적으며, p134는 같은 루프를 "수동으로 실행"하는 것으로 가르친다(둘 다 확인함). 단서는 둘이다: "손으로"의 뜻을 고정할 것(지적 12), "멈춤 장치를 더합니다"가 04b에 상한이 없다는 미확인 전제에 서 있다는 것(지적 11).

고쳐야 할 큰 것은 넷이다: S15의 과장이 실습 관찰과 부딪히는 것(1), "메시지 목록"이 소개 없이 원리의 근거로 쓰이는 것(2), RAG 답변 단계에 근거 프롬프트 개념이 없는 것(3), 입력 이스케이프에 관찰이 없는 것(4). 나머지는 묶음 사이 표기(RAG 병기 · 사이클 낱말 · 아이콘)와 관찰 방법의 구체화다.

6. **Claude Code의 도구 호출 = 오전의 호출 기록** — 오후 연결의 핵심 한 문장(지적 17).

실습 없는 개념(개념은 있는데 확인이 없음)
1. 입력 이스케이프(N03 → LAB05 관찰 없음 — 지적 4)

3. 관찰 가능성(LAB05 칩에만 등장 — 지적 4, 낱말 교체)

오후 연결(검토 항목 7): "오전 · 내가 조립 → 오후 · 이미 조립된 것"(S21), "오전에는 우리가 두뇌에 손발을 달았고, Claude Code는 손발이 이미 달린 내 PC의 에이전트입니다"(S22), "같은 문 · 같은 열쇠"(S23)로 한 문장 연결은 충분하다. 하네스는 S21 한 곳, Skill · MCP · Subagent · Hook은 C04 노트 한 줄과 부록 A04, HITL은 N03 노트와 A10 — 필요한 만큼만 있다. 부족한 것은 LAB07의 관찰 문장 하나다(지적 17).
