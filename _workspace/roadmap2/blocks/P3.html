출처: Yao et al., 2022, ReAct: Synergizing Reasoning and Acting in Language Models · Anthropic, Building effective agents · LangChain SQL 안전 지침(SQL Agent 가이드 내)

Agent는 두뇌가 손발을 조종하는 것입니다. 왼쪽 열처럼 한 번 묻고 한 번 답하면 LLM 호출입니다. 가운데 열처럼 도구 결과를 보고 다음에 무엇을 할지 다시 판단하기를 되풀이하면 Agent입니다. 판단은 모델이 다음 행동을 고르는 것이고, 행동은 모델이 요청하고 코드가 실행하는 도구 호출이며, 관찰은 그 결과를 메시지 목록에 붙여 다시 보는 것입니다. ReAct 논문은 판단을 '생각'이라고 부릅니다. 판단은 기록에 따로 찍히지 않을 수 있는데, 어느 도구를 어떤 값으로 부르자는 호출 요청이 판단의 결과입니다. 호출 요청이 없으면 끝납니다. 다만 끝나지 않고 계속 돌 수도 있습니다. 그래서 맡기는 만큼 멈춤 장치를 함께 둡니다. 코드에는 max_iterations라는 이름으로 적혀 있고, 이어지는 실습의 웹 화면판에는 5회로 걸려 있습니다. 표지에서 드린 질문의 답이 여기 있습니다. 상한을 올려도 답은 좋아지지 않습니다. 멈추게 하는 값이기 때문입니다. 프롬프트에 위험한 조회는 하지 말라고 적는 것은 지침일 뿐 막는 장치가 아닙니다. 그래서 도구에 넣는 값은 조회문을 바꾸지 못하게 코드가 처리합니다. 조회만 허용하는 권한은 오늘 실습 코드 이야기가 아니라 업무에 옮길 때의 일반 원칙이고, 사람이 승인하는 방법과 함께 부록에 두었습니다. 이 Agent를 동료도 쓸 수 있게 화면에 올립니다. 먼저 그 화면의 구조를 보겠습니다.

웹앱의 화면·처리·데이터

Streamlit 앱도 화면·처리·데이터로 나눠 읽습니다.

입력을 받고, 데이터를 조회해 처리한 뒤 화면에 다시 보여 주는 전체 흐름을 흔히 풀스택이라 부릅니다. 화면·서버 기술을 다 배우기 전에, 바꿀 곳이 화면·처리·데이터 세 부분 가운데 어디인지부터 알아봅니다.

개념 예시 · 함수 이름은 가상 · 실제 실습 코드와 다를 수 있음

if q:

    st.write(ans)         # 화면: 결과

Streamlit 공식 문서 설명처럼 Python 서버가 코드를 실행하고 브라우저는 화면을 보여 주는 구조라서, 이 앱은 화면과 처리 사이에 별도 백엔드 서버를 두지 않았고, 모델에는 채팅용 키로, 사내 데이터에는 데이터 조회용 토큰으로 각각 요청합니다. Coding Agent의 작동 방식

오전에는 우리가 두뇌에 손발을 달았고, Claude Code는 손발이 이미 달린 내 PC의 에이전트입니다.

Claude Code는 모델에 파일·명령 도구를 붙여 판단→행동→관찰을 반복하는 Coding Agent입니다. 웹 채팅은 주로 대화로 답하고, Claude Code는 내 PC의 파일과 명령을 도구로 씁니다. 오후에는 이 흐름으로 오전에 만든 장비 조회 Agent를 읽고, 시연과 선택 과제의 대상으로 씁니다. 다른 도구보다 항상 낫다는 뜻은 아닙니다.

출처: Claude Code How Claude Code works · Building effective agents

오전에 만든 장비 조회 Agent가 오후 시연과 선택 과제의 대상이고, 이번 구간의 목표는 Claude Code를 연결해 처음 실행하고 오전 실습 폴더를 읽게 하는 것입니다. 오전에는 우리가 두뇌에 손발을 달았고, 오후에는 손발이 이미 달린 내 PC의 에이전트, Claude Code에게 일을 맡깁니다. 웹 채팅은 주로 대화로 답하고, Claude Code는 내 PC의 파일과 명령을 도구로 씁니다. 자동완성이 아니라 스스로 읽고 실행하는 Agent입니다. 오전 Agent 실습에서 본 반복이 여기서는 파일 읽기와 명령 실행으로 바뀐 것뿐입니다. Claude Code는 모델 자체가 아니라, 모델에 파일 읽기·수정·명령 실행 도구와 실행 환경을 붙여 프로젝트 자체를 다루는 프로그램입니다. 오른쪽 열의 그림처럼 모델이 다음 행동을 판단하고, 도구로 행동하고, 파일과 실행 결과를 관찰한 뒤 다시 판단하는 반복이 핵심입니다. 호출 요청이 없으면 끝나는 것도 오전의 Agent 루프와 같습니다. 이 흐름을 한 번에 이어갈 수 있어서 이번 실습에 쓰는 것이고, 다른 도구보다 항상 낫다는 뜻은 아닙니다. 오전 조회 도구와 지금 볼 파일 수정 도구의 공통점을 한 가지만 말해 주세요. 그렇다면 Claude Code가 접속하는 문은 오전과 같을까요, 다를까요? 다음 장에서 확인합니다.

아침에 그린 세 층을 기억하시지요. 코드는 내 PC에서 돌고, 환경 파일에 적은 주소와 채팅용 키가 사내 LLM 게이트웨이로 이어 주던 그림입니다. 오후도 같은 그림입니다. 내 PC에서 도는 것이 실습 코드에서 Claude Code로, 환경 파일이 설정 파일로 바뀌었을 뿐, 문도 열쇠도 오전 그대로입니다. 다른 점은 이 에이전트가 내 PC에서 파일을 읽고 명령을 실행한다는 것이고, 그래서 Claude Code는 내 PC의 에이전트입니다. 설정 전에는 바깥 주소로 가려 하고, 설정하면 오전과 같은 사내 문으로 갑니다. 다만 파일과 명령이 내 PC에서 실행돼도, 요청과 읽은 파일 내용은 모델 쪽으로 전송됩니다. 로컬에서 실행한다는 것만으로 자료가 내 PC에만 머문다고 볼 수 없으니 보낼 자료의 범위를 먼저 확인합니다. 환경 파일과 설정 파일처럼 열쇠가 든 파일은 읽히지 않습니다. 아래 회색 상자처럼 다른 앱 화면을 조작하거나 사내 시스템에 접근하는 일은 별도 도구와 권한이 있어야 합니다. 파일 읽기, Python 실행, 다른 프로그램 화면 클릭 가운데 지금 환경에서 바로 될 것 같은 것을 예상해 보시고, 맞는지는 이어지는 실습 07에서 직접 확인합니다. 이제 그 설정 파일을 직접 열어 보고 Claude Code를 처음 실행합니다.

Claude Code는 내 PC의 에이전트입니다. 프로그램 설치는 사전 과제로 마치셨으니 오늘은 연결과 첫 실행만 합니다. 먼저 설정 파일, 곧 settings.json을 열어 주소와 채팅용 키가 들어 있는지 확인하고, 없으면 오전 환경 파일에 적었던 그 채팅용 키를 넣습니다. 확인할 것은 열쇠입니다. 오전과 같은 열쇠이고, 주소는 같은 사내 LLM 게이트웨이를 가리키지만 글자는 다를 수 있습니다. 열쇠 값은 내 화면에서만 확인하고, 화면을 함께 볼 때는 열지 않습니다. 이어서 Claude Code를 실행해 인사를 건네고, 답이 오면 연결 상태를 확인합니다. 공식 문서 기준으로는 /status를 입력하면 지금 어느 주소로, 어떤 인증으로 가고 있는지 볼 수 있습니다. 첫 실행에서 연결 오류가 보여도 정상입니다. 설정 전이라 바깥 주소로 가려는 것이고, 설정 파일을 확인하면 풀립니다. 이 열쇠에는 일일 한도가 있고, 남은 한도는 사내 모델 운영 페이지에서 확인합니다. 설치가 안 된 분은 짝을 정해 같은 화면으로 진행하시고, 인터넷에서 찾은 다른 접속 방식으로 우회하지는 않습니다. 첫 인사에 답이 왔으면, 이제 오전 실습 폴더를 읽혀 보겠습니다.

Claude Code의 설명이 곧 정답은 아니므로 판단은 우리가 합니다. 여유가 있으면 마지막 요청으로 공식 문서를 참고하게 해 보시고, 설정 방법처럼 자주 바뀌는 내용은 검색보다 공식 문서가 먼저라는 점을 기억해 두세요. 환경 파일에는 열쇠가 들어 있으므로 읽히지 않습니다. 화면을 함께 볼 때도 열지 않습니다. 파일 읽기는 승인 없이 일어날 수 있어서, 읽히고 싶지 않은 파일은 요청문에서 미리 뺍니다. 승인 요청은 명령 실행과 파일 수정에서 뜹니다. 오전에 본 '요청은 모델, 실행은 프로그램' 사이에 사람이 끼어드는 자리이니, 무엇을 하려는지 읽고 나서 승인하시고, 모르겠으면 아니오를 고른 뒤 손을 들어 주세요. 이번 실습은 읽기와 설명까지이고, 파일 수정은 선택 과제와 자유 실습에서 계획을 세운 뒤에 합니다. 읽히는 것까지 해 봤습니다. 이어서 같은 도구를 어떤 방향으로 쓸 수 있는지 세 가지를 보겠습니다.
