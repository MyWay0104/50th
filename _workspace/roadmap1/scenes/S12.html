LangChain의 역할

LangChain은 연결을 표준화할 뿐, 모델을 똑똑하게 만들지 않습니다.

두 코드는 같은 요청을 같은 서버로 보냅니다. 이번 실습은 검색 결과를 모델 호출에 잇는 부분에 LangChain을 쓰며, 단순 호출이면 SDK로 충분합니다.

from openai import OpenAI
client = OpenAI(base_url=BASE_URL)
msgs = [{"role": "user", "content": prompt}]
res = client.chat.completions.create(
    model=MODEL, messages=msgs)
print(res.choices[0].message.content)
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model=MODEL,
                 base_url=BASE_URL)
res = llm.invoke(prompt)
print(res.content)

두 코드는 같은 일을 합니다. 근거와 질문을 담은 prompt를 같은 서버로 보내고 답을 받습니다. 단순 호출 하나라면 왼쪽처럼 SDK로 충분하고, 코드가 짧다고 성능이 좋은 것도 아닙니다. LangChain의 장점은 모델, 메시지, 검색기, 도구를 같은 방식으로 연결하게 해 준다는 데 있고, 모델을 더 똑똑하게 만들어 주지는 않습니다. 화면 아래 띠는 세 도구를 제어 수준이라는 한 축으로 놓아 본 것인데, 오른쪽으로 갈수록 좋은 것이 아니라 흐름을 얼마나 직접 제어하느냐의 차이입니다. LangGraph는 흐름을 직접 설계해야 할 때, Deep Agents는 계획·파일·위임이 미리 묶인 틀로 긴 작업을 맡길 때 고르는 선택지라서, 순서대로 다 배울 필요 없이 부록의 프레임워크 선택 장면에 두었습니다. 실습 코드에서 질문, 검색 결과, 모델 응답이 각각 어디 있는지 짚어 보세요.
