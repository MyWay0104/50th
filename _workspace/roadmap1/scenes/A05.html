부록 · 실행 오류 점검

막히면 접속부터 파일 경로까지 한 층씩 좁힙니다.

호환 API라도 모든 옵션이 똑같이 동작하지는 않습니다. 오류 원문을 남기고 한 번에 한 가지만 바꿔 다시 실행합니다. 주소·계정·키는 사내 실행 가이드에서 확인합니다.

  1. 1
    접속서버 응답·인증 오류인지 먼저 구분예: 콘솔 인코딩 오류로 서버가 안 뜸
  2. 2
    패키지설치 판본을 실습 가이드와 비교예: 호환 서버용 임베딩 옵션 누락
  3. 3
    모델 기능도구 호출·임베딩 지원 여부 확인예: 임베딩 모델 바꾸면 벡터 새로 생성
  4. 4
    파일 경로코드가 실행되는 위치 기준으로 확인예: 실행 위치가 달라 파일 못 찾음

실습 중 막히면 오류가 어느 층에서 났는지부터 좁히는 것이 빠릅니다. 먼저 서버가 떠 있고 응답하는지, 인증 오류인지를 구분하는데, 한글 Windows에서는 로그를 파일로 넘길 때 콘솔 인코딩 오류로 서버가 아예 뜨지 않는 경우도 있습니다. 접속이 되면 설치된 패키지 판본이 실습 가이드와 같은지 보고, OpenAI 호환 서버에 임베딩을 요청할 때 라이브러리의 토큰 길이 검사 옵션을 꺼야 하는 경우처럼 호환 API라고 모든 옵션이 똑같이 동작하지는 않는다는 점을 기억하세요. 그다음 사용 중인 모델이 도구 호출이나 임베딩을 지원하는지 확인하고, 임베딩 모델을 바꿨다면 기존 벡터와 차원이 맞지 않을 수 있으니 문서 벡터를 새로 만들어야 합니다. 마지막으로 코드가 실행되는 위치를 기준으로 파일 경로가 맞는지 확인합니다. 오류 원문을 그대로 남기고 한 번에 한 가지만 바꿔 다시 실행해야 무엇이 원인이었는지 알 수 있습니다. 카드 아래 예시는 실제 문제 해결 사례를 일반화한 것이고, 주소·계정·키·설치 명령은 사내 실행 가이드에서 확인하며, 오후 Claude Code 연결은 오전 API와 별도 경로로 점검합니다.
