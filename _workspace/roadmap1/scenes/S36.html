Skill과 도구 연결의 역할

Skill은 절차 파일 — 네 기능은 위아래가 아닌 다른 역할입니다.

Skill은 반복 절차를 SKILL.md에 적어 둔 것입니다. 모델은 평소 이름·설명만 보다가, 쓸 Skill을 고르면 본문을 읽습니다. 넷 모두 모델 학습이 아니며 권한은 실행 환경 설정이 정합니다.

출처: Claude Code Skills · Features overview 문서

Skill은 반복하는 절차와 참고자료를 파일로 적어 두고 필요할 때 불러 쓰는 방법이며, 모델을 다시 학습시키는 기능은 아닙니다. 화면 아래 줄처럼 처음에는 각 Skill의 이름과 설명만 목록으로 보이고 작업에 맞는 것을 고를 때 본문 절차를 읽는데, 이런 방식을 Progressive Disclosure(점진적 공개)라고 부르며, 필요한 순간에만 본문을 읽어 맥락을 아낍니다. 위 줄의 네 카드는 위아래 단계가 아니라 나란히 놓인 다른 역할이라 필요한 것만 골라 조합합니다. 오늘 손으로 해 볼 것은 Skill 하나이고, 나머지 셋은 이름과 역할만 알아 두시면 됩니다. 오전에는 SQL 조회 함수를 우리 코드에서 직접 도구로 붙였는데, MCP는 사내 문서나 DB 같은 외부 시스템의 도구를 정해진 규약으로 연결하는 방식이고, Subagent는 예외 입력만 따로 점검하게 하는 것처럼 떼어 낼 수 있는 하위 작업을 별도 맥락에서 맡기며, Hook은 정해진 시점에 동작을 자동으로 겁니다. MCP는 앱 N개와 도구 M개를 하나씩 잇는 대신 규약 하나로 연결 수를 N+M으로 줄이는 발상이고, 자세한 예시는 부록의 MCP·Subagent·Hook 장면에 두었습니다. 앞 시간의 CLAUDE.md가 모델이 읽는 지침일 뿐 권한을 강제하지 않았던 것처럼, 오늘 쓰는 절차 파일도 작업 방법을 알려 줄 뿐 실행 권한은 실행 환경의 설정이 정합니다. 같은 자료를 매번 같은 규칙으로 정리하고 싶다면 넷 중 무엇이 맞을까요? 한 분만 답해 주세요. 네, Skill입니다. Skill은 어떻게 정리할지 절차를 적은 것이고, Hook은 'Claude Code가 파일을 고친 직후마다'처럼 언제 동작할지를 정하는 쪽이라 둘을 함께 쓸 수도 있습니다.
