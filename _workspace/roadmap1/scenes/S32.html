먼저 Claude Code에게 오전 앱의 구조와 수정할 위치를 설명하게 하고, 다음으로 바꿀 곳과 완료 조건을 담은 계획을 받아 우리가 읽고 확인합니다. 이어서 계획한 범위만 구현하게 하는데, 전체 앱을 다시 짜거나 기능을 여러 개 붙이는 것은 이번 범위에 넣지 않습니다. 마지막으로 없는 키워드 같은 새 기능용 입력과 오전에 정상 동작하던 질문을 둘 다 실행하고, 바뀐 내용도 확인합니다. 기본 과제인 검색 결과 없음 안내가 이미 되어 있다면 결과 다운로드로 바꿔 진행하세요. 왼쪽 승인 요청 카드는 요청 화면의 모양을 일반화한 개념 예시로 실제 화면과 다를 수 있는데, Claude Code가 이런 식으로 파일 수정이나 명령 실행 승인을 요청하면 무엇을 하려는지 읽고 나서 승인하고, 무엇을 하려는지 모르겠으면 아니오를 고른 뒤 손을 들어 주세요. 부록의 HITL, 곧 사람이 작업 흐름 중간에서 승인하는 방식을 오늘 직접 겪는 장면이고, 공식 문서 Permissions도 이런 승인 범위를 설정으로 정하는 방법을 설명합니다. 앱의 모델 호출이 막히면 준비된 결과로 화면과 규칙 부분만 확인하고, Claude Code 환경이 준비되지 않은 분은 앞 시간에 정한 짝과 같은 화면으로 진행합니다.
