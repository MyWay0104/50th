출처: LangChain SQL Agent 가이드 · Anthropic, Building effective agents

오늘 만든 작은 도구를 실제 업무에 쓰기 전에는 진행 단계 띠의 다섯 가지를 먼저 확인합니다. 권한은 프롬프트 문장이 아니라 실행 환경에서 읽기 범위와 허용 테이블로 제한해야 하고, 날짜 기준·단위·결측값 의미 같은 데이터 정의는 사람마다 다르면 코드가 맞아도 답이 달라지므로 누가 관리하는지까지 문서로 남깁니다. 정답을 아는 입력, 자료가 없는 질문, 도구가 실패하는 상황을 모은 작은 정답 세트로 각각 어떻게 동작하는지 확인합니다. 모델과 도구가 어떤 순서로 불렸는지, 응답 시간과 호출량이 얼마인지 기록해 두면 문제가 났을 때 어디서 막혔는지 찾을 수 있고, 이런 기록을 모아 보여 주는 관측 도구도 있습니다. 누가 무엇을 바꿨는지와 사용자 피드백을 받을 창구도 미리 정합니다. 이 순서는 여러 체크리스트를 합쳐 다시 정리한 권장안입니다. 화면이 뜨는 것과 업무에 쓸 준비가 된 것은 다르다는 점을 기억해 주세요.
