# 사내 실습자료 흐름 (사용자 제공 · 2026-09-17)

사용자가 사내에서 이미 만든 실습 자료의 흐름이다. 보안상 자료 자체는 저장소에 없고 개념 수준으로만 전달됐다. 덱 재구성의 **기준 흐름**이다.

사용자의 핵심 요구: **"실습 코드를 기반으로 사내에서 실습을 하게 되지만, 각 파트에서 코드만 쓰고 개념은 모르는 게 제일 싫다."** 즉 실습 단계마다 그 단계의 원론적 개념이 짝으로 붙어야 한다. 원하던 강의 흐름은 `docs/SK하이닉스_AI 에이전트 프레임워크 구현 (사당교육 4일).pdf`의 흐름이다.

## 오전

1. **사내 환경 세팅**
   - VS Code, Python 설치 등 기본 구성
   - 사내 vLLM 서버의 LLMOps 페이지에서 환경변수 세팅 등
2. **LLM 단순 호출**
   - 프롬프트 변화에 대한 답변 변화 실습
   - temperature 변화에 따른 답변 변화 실습
   - "럭키비키 긍정봇" 구현·실습 (무엇이든 긍정적으로 이야기해 주는 봇, 단순 프롬프팅으로 구현)
3. **RAG 필요성 대두 → RAG 구현**
   - 단순 웹 크롤링으로 AI 없는 RAG 구성 (네이버 기사 페이지)
   - FAISS 기반 청킹·임베딩 과정 실습
   - RAG VectorDB를 LLM에 붙여 단순 RAG 기반 요약 실습 (리트리버 툴 없이 URL 하나만 크롤링해서 AI가 요약만 해 줌)
4. **Tool 필요성 대두 → 사내 DataLake(RDBMS) SDK로 API 구현**
   - API 기반으로 사내에 존재하는 특정 테이블을 Python 코드로 불러옴
   - 단순 호출로 테이블 상태 조회
   - 불러온 SQL 테이블을 토대로 RAG Agent 구현 (Text-to-SQL 없이, 정해진 테이블을 정해진 SQL 쿼리로 하드코딩해 Raw로 불러온 뒤 RAG Agent로 구현 — SQL Tool)
5. **Streamlit 기반 풀스택 데모형 에이전트 구현 실습**
   - SQL 테이블 기반으로 특정 장비의 위치 정보와 진행 공정을 조회 → 반환
   - 챗봇 형식

## 오후

1. **사내 Claude Code 설치·환경설정 안내**
2. **Claude Code 기본 개념·사용 방향 설명**
   - Claude Code를 Agent 그 자체로 활용 (예: 로컬 파일 데이터 분석)
   - Claude Code를 원래 목적인 coding agent로 활용 (예: 단순 Python 스크립트 기반 엑셀 비교 프로그램, Part Finder Agent 구현)
   - Claude Code와 Obsidian 접목을 통한 지식 자산화 → 궁극적 목표는 "나만의 Agent 만들기" (예: 공정 Engineer 1개월차인데 새로운 개념을 수시로 넣어 주고 ingest, 다시 query → 나의 의사결정과 배움 과정을 함께 하는 중)
3. **Claude Code를 통한 자유 실습**
   - 방향이 다양해 어느 정도 자율성이 보장되는 시간
   - 추천 예시: CSV 파일 핸들링, 오전에 구현한 데모형 풀스택 에이전트를 Claude Code로 조금씩 바꿔 보며 소형 개발 흐름 체화

## 화면 표기 제약 (deck-rules.json)

- 사내 주소·모델명·키·사내 SDK 실제 이름은 화면에 쓰지 않는다. 역할 이름(예: "사내 데이터 조회 라이브러리")으로 쓴다.
- 시간 정보는 첫 시간표(G01) 한 장에만.
- 화면 문장은 존댓말. 출처는 공식 문서·논문만.
- 장면마다 이미지·인포그래픽 하나 이상.
