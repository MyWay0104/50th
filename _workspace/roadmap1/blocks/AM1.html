실습 환경의 세 층

코드는 내 PC에서 돌고, 계산은 사내 추론 서버에서 하며, 환경변수가 둘을 잇습니다.

설치는 사전 과제로 마쳤으니 오늘은 세 층이 이어지는지만 확인합니다. 코드에 OpenAI라는 이름이 있어도 요청은 환경변수에 적은 서버로 갑니다.

개념 예시
내 PC
실습 코드VS Code와 Python요청을 보냄
⇄
환경변수
환경변수주소·모델·키사내 모델 운영 페이지에서 받음
⇄

주소·모델명·키 대신 역할 이름으로 표시 · 한 층만 어긋나도 첫 응답이 오지 않습니다

요청 목적지를 정하는 두 줄 · 개념 예시

    model=MODEL,        # 모델 이름
    base_url=BASE_URL,  # 서버 주소
)   # 키는 환경변수에서 읽음

출처: vLLM Online Serving 문서 · LangChain Models 문서

실습 환경은 세 층으로만 기억하시면 됩니다. 코드는 내 PC의 VS Code와 Python에서 돌고, 실제 계산은 사내 추론 서버에서 vLLM이 모델을 실행해 처리하며, 그 둘을 잇는 것이 서버 주소, 모델 이름, 키 세 개의 환경변수입니다. 환경변수 값은 사내 모델 운영 페이지에서 받아 코드 밖에 두고, 오른쪽 코드의 model과 base_url 두 줄이 그 값을 읽어 요청의 목적지를 정합니다. 그래서 코드에 OpenAI라는 이름이 있어도 요청이 OpenAI로 가는 것은 아니고, API는 요청과 응답 형식의 약속, SDK나 LangChain은 그 호출을 돕는 Python 도구라는 정도만 알아 두시면 됩니다. VS Code, Python, Claude Code 설치는 사전 과제로 마치셨으니 오늘은 첫 호출이 되는지만 확인하고, 첫 응답이 오면 content와 함께 토큰 사용량도 같이 보겠습니다. 이 토큰이 오늘 내내 길이와 비용을 재는 단위입니다. 질문 하나 드리겠습니다. 환경변수 한 줄이 틀리면 세 층 중 어디에서 막힐까요? 주소가 틀리면 서버에 닿지 못하고, 모델 이름이 틀리면 서버가 거절하고, 키가 틀리면 인증에서 막힙니다.

LLM의 응답 생성

LLM은 사실을 조회하지 않고 다음 토큰의 확률 분포를 계산합니다.

보통의 호출은 학습된 모델로 계산만 하므로, 질문을 더 보낸다고 모델이 재학습되지 않습니다. 한 번에 넣을 수 있는 입력·출력 길이의 한도를 컨텍스트 윈도우라고 합니다. 다음 실습에서 바꿀 temperature 값은 3단계의 선택에 영향을 줍니다.

  1. 1
    토큰으로 나누기회의 | 내용을 | 세 | 줄로
  2. 2
    다음 토큰 분포 계산후보: 요약 · 정리 · …
  3. 3
    선택하고 반복'요약'을 골라 뒤에 붙임
고른 토큰을 입력 끝에 붙여 2단계로 돌아가기 — 답이 끝나거나 길이 한도에 닿을 때까지 반복

개념 예시 · 실제 토큰 분할은 모델마다 다름 · 확률 수치 없음 · 길이 한도 = 컨텍스트 윈도우

출처: Vaswani et al. 2017 · Ouyang et al. 2022 (지시 수행 학습)

용어를 먼저 정리하면, AI 안에 데이터로 패턴을 학습하는 머신러닝이 있고 그 안에 신경망을 쓰는 딥러닝이 있으며, 오늘 다루는 LLM은 딥러닝 기반의 언어 모델입니다. 대체 관계가 아니라 포함 관계이고, 오늘은 그중 LLM이 답을 만드는 방식만 가져갑니다. LLM은 입력을 토큰이라는 단위로 나누고, 지금까지의 문맥으로 다음 토큰 후보들의 가능성을 계산해 하나를 고르는 과정을 반복합니다. 화면의 세 카드 아래 줄처럼, 고른 토큰을 입력 끝에 붙여 다시 2단계로 돌아가는 방식을 자기회귀 생성이라고 합니다. 토큰은 단어 하나와 항상 같지 않고, 나누는 방식은 모델마다 다릅니다. 학습 단계에서는 모델 매개변수를 바꾸지만, 오늘 우리가 하는 호출은 이미 학습된 모델로 결과를 계산할 뿐입니다. 토큰 수는 비용과 속도를 재는 단위이면서, 한 번에 넣을 수 있는 입력과 출력 길이의 한도인 컨텍스트 윈도우를 재는 단위이기도 합니다. 이 한도는 다음 RAG 구간에서 자료를 나누는 첫 이유로 다시 나옵니다. 그러면 재학습이 아닌데도 같은 질문의 답이 달라진다면, 세 단계 중 어디에서 갈리는지 한 분만 답해 주세요.

temperature는 다음 토큰을 고를 때 선택의 다양성에 영향을 주는 값입니다. 화면의 막대처럼 같은 후보라도 값을 낮추면 확률이 높은 후보 쪽으로 몰리고, 높이면 여러 후보로 퍼져서 표현이 호출마다 달라지기 쉽습니다. 하지만 어느 쪽이든 모델이 모르는 정보를 더하거나 사실을 검증해 주지는 않습니다. 낮은 값에서도 틀릴 수 있고, 서버 환경에 따라 모든 실행이 완전히 같다는 보장도 없습니다. 같은 선택 단계에서 후보 범위를 좁히는 Top-K·Top-P 같은 값도 있지만, 오늘 실습에서는 temperature 하나만 바꿔 봅니다. 같은 질문을 여러 번 보내면 어떤 차이가 날지 먼저 예측해 보세요.

메시지 역할과 프롬프트

system이 규칙을 정하고, user가 묻고, assistant가 답합니다.

모델에 보내는 것은 문장 하나가 아니라 역할이 붙은 메시지 목록입니다. 모델은 목록에 있는 것만 보므로, 앞의 답을 다시 넣지 않으면 이전 대화를 모릅니다.

system규칙·말투·역할한 줄이 답 전체를 바꿈
user이번 질문매번 새로 보냄
assistant모델의 답다음 요청에 다시 넣어야 기억
예시 몇 개를 함께 넣으면 답의 모양이 예시를 따라옵니다
역할이 붙은 메시지 목록 · 개념 예시
messages = [
  ("system", "정중하게 답합니다"),   # 규칙
  ("user", "첫 질문"),
  ("assistant", "첫 답"),  # 앞 답을 다시 넣음
  ("user", "두 번째 질문"),
]

코드 위치: 프롬프트 구성부 · 긍정봇 — 실습 가이드 해당 장

출처: LangChain Messages 문서 · OpenAI Chat Completions 가이드

모델에 보내는 것은 문장 하나가 아니라 역할이 붙은 메시지 목록이고, 역할은 세 가지만 기억하시면 됩니다. system은 규칙과 말투와 역할을 정하는 자리라 한 줄만 바꿔도 답 전체의 성격이 바뀌고, user는 이번 질문이며, assistant는 모델이 낸 답입니다. 오른쪽 코드처럼 앞의 답을 assistant 메시지로 다시 넣어야 모델이 이전 대화를 참고할 수 있고, 넣지 않으면 매번 처음 만난 것처럼 답합니다. 이 성질은 이어지는 실습의 긍정봇에서 직접 확인합니다. 아래 상자의 한 줄처럼 원하는 답의 예시를 몇 개 같이 넣으면 답의 형식과 말투가 그 예시를 따라오는데, 이 방식을 few-shot 프롬프팅이라고 부릅니다. 예측 질문 하나 드리겠습니다. system 한 줄을 바꾸면 답의 무엇이 달라질까요? 내용이 달라질지, 말투와 형식이 달라질지 예측해 두시고 실습에서 확인해 보세요.

먼저 설치와 환경변수를 확인하고 준비된 첫 호출을 실행해, 첫 응답의 content와 토큰 사용량이 함께 오는지 봅니다. 이것이 앞에서 본 세 층이 이어졌다는 확인입니다. 이어서 질문은 그대로 두고 system 한 줄만 바꿔 답의 말투와 형식이 어떻게 달라지는지 보고, 다음으로 temperature 두 값에서 같은 질문을 각각 세 번 이상 보내 표현의 흔들림을 비교합니다. 차이가 없었다는 것도 관찰 결과로 적어 두세요. 네 번째로 럭키비키 긍정봇을 규칙 없이, system 한 줄만, 예시 추가의 세 단계로 만들어 답이 어떻게 바뀌는지 비교하고, 완성된 봇에 두 번째 말을 걸어 앞 대화를 기억하지 못하는 것을 확인합니다. 앞 장의 assistant 메시지를 다시 넣지 않았기 때문이고, 이 결핍의 해법은 오후에 다시 다룹니다. 마지막으로 학습 이후에 나왔을 수 있는 최신 자료를 물어보고, 그럴듯하지만 근거 없는 답이 나오는지 표시합니다. 이것을 환각이라고 부르고, 확률로 다음 토큰을 만드는 방식의 부작용입니다. 접속이 안 되는 분은 준비된 출력으로 같은 비교를 계속하되 직접 실행한 결과와 구분해 두세요. 완료 조건은 바꾼 것 하나와 달라진 것 하나를 한 문장으로 말하는 것이고, 최신 자료 질문에서 본 한계는 다음 구간에서 외부 근거로 채워 보겠습니다.
