## 2. 제안 흐름 (초안 A)

`유지`=현 장면 유지, `이동`=위치 변경, `재구성`=내용 교체, `신설`=새 장면, `부록`=부록으로 내림, `삭제`=삭제 후보.

### 도입 (4장)
- S01 표지 유지 · G01 시간표 **재구성**(구간 이름 변경) · G00 공부법 유지 · S02 강사 소개 유지(세 사례의 재등장 위치 갱신)

### 오전 1 · 실습 환경 (2장)
- **신설 E01** "실습 환경의 세 층": 내 PC(VS Code·Python) ⇄ 환경변수(주소·키·모델명) ⇄ 사내 추론 서버(vLLM). S06(모델·서버·API)의 그림·문구를 여기로 **이동**해 통합. 개념: "코드는 내 PC, 계산은 서버, 환경변수가 다리".
- **신설 E02** 실습 0 · 환경 확인 안내판: 설치 확인 → 환경변수 → 첫 호출 성공. 캡처 자리표시.

### 오전 2 · LLM 단순 호출 (개념 4 + 실습 2)
- S03 AI·ML·LLM 관계 유지(축약 가능)
- S04 다음 토큰 예측 유지
- **신설 L01** "메시지 역할과 프롬프트": system / user / assistant 세 역할, system이 답의 톤·규칙을 정함. 4일 교안 p42–44, 5일 교안 p66–68(system→context→role 누적 실험) 참고.
- S07 temperature 유지
- S05 Attention → **부록**(A01과 통합)
- **재구성 S08** 실습 1 · 프롬프트와 temperature: ① 같은 질문·다른 system 프롬프트 ② temperature 두 값 3회 비교 ③ 최신 자료 질문(한계 표시 → RAG 동기)
- **신설 L02** 실습 2 · 긍정봇: system 프롬프트 + 예시 몇 개(few-shot)로 "무엇이든 긍정적으로" 답하는 봇. 관찰: 규칙 한 줄 추가마다 답이 어떻게 바뀌나. 개념 짝: system 역할·few-shot.

### 오전 3 · RAG (개념 5 + 실습 2)
- S09 외부 자료가 필요한 질문 유지(실습 1 ③에서 이어짐)
- **재구성 S11** "AI 없는 RAG": 기사 URL → 본문 추출 → 파일. 이것만으로 '찾아서 읽기'는 된다. 본문이 실제로 들어왔는지 확인(현 S11의 핵심 유지).
- S10 RAG 기본 구조 유지(인덱싱 / 검색·답변 두 시점)
- **승격 A02→R01** "청킹·임베딩·벡터 검색": 왜 나누나(컨텍스트 한계·검색 정밀도), 조각 크기·겹침, 임베딩=뜻을 숫자로, 가까운 벡터 찾기. 5일 교안 p80–83(코사인 유사도 3문장 비교) 참고.
- S12 LangChain 역할 유지(축약)
- **재구성 S13** 실습 3 · 크롤링→청킹→임베딩→FAISS 저장: chunk_size 바꿔 조각 수 변화 관찰, 유사도 점수 확인.
- **신설 R02** 실습 4 · 벡터 저장소를 모델에 붙여 요약: URL 하나 요약. 관찰: 요약 문장이 본문에 있나.
- S14 답변과 근거 확인 유지(→ 정확한 집계는 Tool로, 동기 연결)

### 오전 4 · Tool과 SQL Agent (개념 4 + 실습 2)
- S15 정확한 조회와 계산 유지
- **신설 T01** "데이터 API로 테이블 불러오기": 사내 데이터 조회 라이브러리(역할 이름) → 정해진 쿼리 → DataFrame. 이것은 아직 AI가 없는 '단순 호출'. 상태 조회 예시.
- S16 Tool 호출 순서 유지(모델은 요청, 프로그램이 실행)
- S17 스크립트·Workflow·Agent 유지
