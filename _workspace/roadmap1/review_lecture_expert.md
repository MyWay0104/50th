## 0. 총평

초안 A는 사용자 흐름과 장면 대응이 정확하다. 문제는 두 가지다. (1) 오전 활동 120분에 실습 안내판 8개는 안내판당 15분이 안 되어 "코드만 돌리고 개념은 모르는" 바로 그 상태를 만든다. (2) 오후 축을 "사용 방향 3가지"로 바꾸면 성과 3·4(완료 조건 전달·검증)를 몸으로 익히는 장면(S25·S28·S31·S33)이 모두 자유 실습 갈래로 밀려 필수가 아니게 된다. 아래에서 실습을 4개로 합치고, 자유 실습 앞에 "공통 미니 과제 15분"을 두는 것으로 두 문제를 동시에 푼다.

## 2. 오전 실습 안내판 8개 → 4개

| 초안 | 제안 | 소단계(개념 짝) | 이유 |
|---|---|---|---|
| 실습 0 + 1 + 2 | **실습 1 · 첫 호출과 프롬프트** | ① 환경변수·첫 호출(E01 세 층) ② system 한 줄 바꾸기(L01 역할) ③ temperature 두 값 3회(S07) ④ 긍정봇: 규칙 한 줄씩 추가(L01 few-shot) ⑤ 최신 자료 질문(→RAG 동기) | 긍정봇은 "system 프롬프트 바꾸기"의 연장이라 별도 안내판이면 개념이 같은데 화면만 는다. 설치(VS Code·Python)는 사전 과제로 빼고 당일은 확인만 한다. |
| 실습 3 + 4 | **실습 2 · 기사 한 편으로 RAG 만들기** | ① 본문 확보·눈으로 확인(S11, AI 없음) ② chunk_size 바꿔 조각 수 보기(R01 청킹) ③ 질문 한 개로 가까운 조각·점수 보기(R01 임베딩) ④ 모델에 붙여 요약·근거 대조(S14) | 청킹→임베딩→요약은 한 코드의 연속 단계다. 나누면 ③에서 "저장만 하고 끝"이라 성취감이 없다. |
| 실습 5 + 6 | **실습 3 · 조회 함수를 도구로** | ① 정해진 쿼리로 테이블 불러오기(T01, AI 없음) ② 상태 조회 값 확인 ③ 같은 함수를 @tool로 붙이기(S16) ④ 정답 아는 질문·결과 없는 질문(S15) | "AI 없는 조회 → 도구로 승격"을 한 화면에 두어야 '모델은 요청, 코드가 실행'이 대비된다. |
| 실습 7 | **실습 4 · Streamlit 데모** 유지 | ① 실행 ② 장비 ID 입력 ③ 입력→함수→화면 짚기 | 층이 다르므로 분리 유지. |

안내판마다 소단계 라벨 옆에 개념 이름(예: "② 역할 · system")을 작은 칩으로 붙이면 사용자의 "코드만 쓰고 개념은 모르는" 우려에 직접 답한다. 막힘 대체 경로(준비된 출력·짝 화면)는 현 S08·S13·S19 문구를 그대로 가져온다.

## 3. 오후 축 변경으로 잃는 것과 지킬 방법

잃는 것: (a) 탐색·계획·구현·검증을 실제로 겪는 실습 6(S32) (b) 완료 조건 6칸을 직접 쓰는 참여(S25) (c) 변경 확인 3분법 + Dokmo(S31) (d) 다른 입력 재확인·예측 먼저(S33) (e) "오전 앱이 오후 작업 대상"이라는 하루 서사. 이 다섯은 G02 성과 3·4의 유일한 실습 근거다.

지킬 방법:
1. **자유 실습 첫 15분을 "공통 미니 과제"로 고정**: 전원이 오전 앱에 "결과 없음 안내" 한 기능을 탐색·계획·구현·검증 4단계로 붙인 뒤 자유 주제로 넘어간다. S32·S33을 안내판 한 장으로 압축해 여기에 둔다. 이렇게 하면 S41의 단계 띠(계획→구현→첫 실행→…)가 그대로 살고 자유 실습 갈래 "오전 앱 개선"은 "여기서 기능 하나 더"가 된다.
2. **S25 요청문 6칸은 방향 ② 직후에 유지**하고 참여 활동("오전 앱에 붙일 기능의 완료 조건 한 문장")을 남긴다. 이 문장이 그대로 공통 미니 과제의 입력이 된다.
3. **S28 4단계는 방향 ② 강사 시연에 라벨로 붙인다**: 시연 화면을 탐색/계획/구현/검증 네 장면으로 끊어 캡처하고, 시연 후 "지금 어느 단계였나요?"를 묻는다.
4. **S31 변경 확인 3분법 + Dokmo는 자유 실습 검증판(S43)에 통합**: "바뀐 줄 / 실행 결과 / 직접 써 보기" 세 칸을 S43 완료 조건 옆에 둔다.
5. 오전·오후 연결 문장: S21 끝 "이 앱이 오후 작업 대상"은 유지하되 "오후 시연과 자유 실습 첫 과제의 대상"으로 정확히 쓰고, S22 노트도 같은 문장으로 맞춘다.

## 6. 인지 부하 · 실습 직전 새 용어 3개 초과 지점

| 지점 | 초안대로면 | 제한 방법 |
|---|---|---|
| E01(S06 통합) → 실습 1 | 내 PC·환경변수·vLLM·API·SDK·LangChain = 6 | 화면은 "내 PC / 환경변수 / 추론 서버" 3개. API·SDK는 노트, LangChain은 RAG 구간. |
| L01 → 실습 1 ④ 긍정봇 | system·user·assistant·few-shot = 4 | few-shot은 용어 없이 "예시 몇 개 넣기"로 소단계 라벨만. |
| S10 + R01 + S12 → 실습 2 | 인덱싱·청킹·임베딩·벡터·FAISS·코사인·chunk_size·overlap·LangChain = 9 | R01은 "나누기·숫자로 바꾸기·가까운 것 찾기" 3개로 고정. FAISS는 안내판에서 "저장소 이름"으로만, 코사인·겹침은 노트. S12는 부록. |
| T01 + S16 → 실습 3 | DataFrame·조회 라이브러리·@tool·tool_calls·docstring = 5 | T01은 "정해진 쿼리 = 조회 함수" 1개, S16은 @tool·tool_calls 2개. docstring은 노트. |
| C01 + C02 + S36 → 방향 시연 | 방향 3 + CLAUDE.md + Skill·MCP·Subagent·Hook = 8 | S36 부록으로. C02는 새 용어 0(오전 S15 원칙 재사용). |

참여 질문: 신설 장면 E01·L01·R01·T01·C01·C02에 예측형 질문이 없다. 각 장에 하나씩 넣어야 구간당 2회가 유지된다(예: L01 "system 한 줄을 바꾸면 답의 무엇이 달라질까요?", R01 "조각을 두 배 크게 하면 조각 수는?", T01 "이 조회에 AI가 관여하나요?").

오해 예방(조사정리 5절): 초안의 "AI 없는 RAG"와 "URL 하나 요약 = RAG"는 표 6행("URL 하나를 전부 읽어 요약하면 항상 RAG Agent")에 걸린다. 실습 2 ①은 "찾아서 읽기(검색만)", ④는 "외부 문서 기반 요약"으로 이름 짓고, 노트에 "질문에 맞는 조각을 골라 넘길 때 RAG라 부른다"를 넣는다. 하드코딩 SQL의 "SQL Agent"도 표 7행("Tool 하나 붙이면 항상 Agent")에 걸리므로 S17에서 "우리 것은 Workflow에 가깝다"를 확인 질문으로 닫는다.
