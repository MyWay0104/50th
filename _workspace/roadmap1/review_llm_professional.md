# llm-professional 검토 · 재구성 초안 A (`draft_restructure.md` v0)

## 총평 (5줄 이내)

- 초안 A의 뼈대(환경 → 단순 호출 → RAG → Tool → Streamlit → Claude Code 세 방향)는 사용자 흐름과 4일 교안 01·02장 순서에 맞고, 신설 L01(메시지 역할)·R01(청킹·임베딩)·T01(단순 호출)은 꼭 필요한 보강이다.
- 다만 실습 1(개념 4개)·실습 3(개념 5개)·실습 5(개념 4개) 앞에 개념이 몰려 있고, 반대로 실습 4(요약)는 직전에 만든 청킹·FAISS를 손으로 확인하지 못해 짝이 끊긴다.
- 4일 교안 p27이 한 장에 두는 다섯 원론(다음 토큰·토큰·컨텍스트 윈도우·temperature·환각) 중 컨텍스트 윈도우·환각은 오전에 이름이 붙지 않은 채 오후 S30에서 처음 나온다. 멀티턴(대화 이력)과 Agent 루프(도구 결과를 보고 다시 판단)도 오전에 없다.
- 오전→오후 연결은 S21·S22 노트에 "모델은 요청, 프로그램이 실행" 한 문장이 있어 통과하지만, "오전에 손으로 묶은 모델+도구+메모리 = 하네스, Claude Code는 이미 묶인 하네스"라는 이름 붙이기(4일 p32)가 빠져 있다.
- 아래 재배치대로 하면 실습마다 직전 개념이 1~2개로 줄고 장수는 늘지 않는다.

## 빠진 개념 / 실습 없는 개념

- **컨텍스트 윈도우**: 오전에 이름이 없고 오후 S30에서 처음 나온다. S04에 한 줄, R01 "왜 나누나"의 첫 이유로 재등장(4일 p69).
- **환각**: S09가 "그럴듯함≠근거"로 현상은 다루지만 이름을 안 붙인다. 실습 1 최신 자료 질문의 관찰 결과에 이름을 붙이고, 4일 p27처럼 "확률 생성의 부작용 → RAG·Tool·검증으로 보완"을 오전 전체의 지도 문장으로 쓴다.
- **대화 이력·메모리**: 오전 어디에도 없다. 긍정봇(실습 2)에서 두 번째 말 걸기, 챗봇(실습 7)에서 thread_id 여부로 두 번 관찰. 핸드북 p18의 "이름을 말했는데 못 기억" 결핍 장면을 노트에.
- **Agent 루프·종료 조건**: S16은 1회 왕복. 루프 화살표와 "도구 호출이 없으면 종료"를 추가해야 S17(Agent는 모델이 다음 행동을 고름)과 S22가 같은 그림이 된다.
- **실습 없는 개념**: S17은 실습 앞에 있으면 실습 없는 개념이 된다 → 실습 6 뒤로. S12 LangChain 역할은 실습에서 관찰할 것이 없다 → 부록.

## 4일 교안 리듬의 하루 축약

"왜 → 개념 → 코드 → 시각화 → 요약" 5단계를 하루 덱에서는 4개 자리로 접는다. **왜**는 별도 장이 아니라 직전 구간 마지막 장(S14·S21 같은 "한계 → 다음")의 마지막 문장과 다음 개념 장 노트의 첫 질문으로. **개념+시각화**는 한 장(도식이 곧 개념). **코드**는 실습 안내판의 "코드 위치 + 관찰할 것"으로만(화면 코드는 3줄 이내, 현 S06·S16 방식). **요약**은 실습 안내판의 완료 조건("바꾼 값과 차이를 한 문장으로")을 수강생이 말하게 하는 것으로 대신하고, 강사 요약 장은 구간당 두지 않는다. 이러면 구간마다 [한계 1장 → 개념 1~2장 → 실습 1장]의 3~4장 리듬이 되어 실습 0~8 아홉 개를 56장 안에 넣을 수 있다.
