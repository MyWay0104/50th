## 6쪽 · S04 · data-skill steps

- 화면: LLM의 응답 생성 LLM은 사실을 조회하지 않고 다음 토큰의 확률 분포를 계산합니다. 보통의 호출은 학습된 모델로 계산만 하므로, 질문을 더 보낸다고 모델이 재학습되지 않습니다. 한 번에 넣을 수 있는 입력·출력 길이의 한도를 컨텍스트 윈도우라고 합니다. 다음 실습에서 바꿀 temperature 값은 3단계의 선택에 영향을 줍니다. 1 토큰으로 나누기 회의 | 내용을 | 세 | 줄로 2 다음 토큰 분포 계산 후보: 요약 · 정리 · … 3 선택하고 반복 '요약'을 골라 뒤에 붙임 고른 토큰을 입력 끝에 붙여 2단계로 돌아가기 — 답이 끝나거나 길이 한도에 닿을 때까지 반복 개념 예시 · 실제 토큰 분할은 모델마다 다름 · 확률 수치 없음 · 길이 한도 = 컨텍스트 윈도우 출처: Vaswani et al. 2017 · Ouyang et al. 2022 (지시 수행 학습)
- 노트: 용어를 먼저 정리하면, AI 안에 데이터로 패턴을 학습하는 머신러닝이 있고 그 안에 신경망을 쓰는 딥러닝이 있으며, 오늘 다루는 LLM은 딥러닝 기반의 언어 모델입니다. 대체 관계가 아니라 포함 관계이고, 오늘은 그중 LLM이 답을 만드는 방식만 가져갑니다. LLM은 입력을 토큰이라는 단위로 나누고, 지금까지의 문맥으로 다음 토큰 후보들의 가능성을 계산해 하나를 고르는 과정을 반복합니다. 화면의 세 카드 아래 줄처럼, 고른 토큰을 입력 끝에 붙여 다시 2단계로 돌아가는 방식을 자기회귀 생성이라고 합니다. 토큰은 단어 하나와 항상 같지 않고, 나누는 방식은 모델마다 다릅니다. 학습 단계에서는 모델 매개변수를 바꾸지만, 오늘 우리가 하는 호출은 이미 학습된 모델로 결과를 계산할 뿐입니다. 토큰 수는 비용과 속도를 재는 단위이면서, 한 번에 넣을 수 있는 입력과 출력 길이의 한도인 컨텍스트 윈도우를 재는 단위이기도 합니다. 이 한도는 다음 RAG 구간에서 자료를 나누는 첫 이유로 다시 나옵니다. 그러면 재학습이 아닌데도 같은 질문의 답이 달라진다면, 세 단계 중 어디에서 갈리는지 한 분만 답해 주세요.

- 노트: 답변이 좋아 보이는지보다, 근거가 그 문장을 실제로 뒷받침하는지를 봅니다. 한 분이 답변에서 문장 하나를 고르고, 그 문장이 들어 있는 기사 문단을 짚어 주세요. 근거 밖의 내용이 나왔다면 화면 오른쪽 표처럼 검색이 잘못된 것인지, 가져온 자료를 잘못 설명한 것인지를 나눠 보면 고칠 위치가 좁아집니다. 오늘은 본문을 통째로 넣었으니 검색 줄은 해당 없고, 조각을 골라 넘기는 구성이 되면 검색 줄부터 봅니다. RAGAS 같은 RAG 평가 도구도 검색 쪽과 답변 쪽을 나눠서 점수를 매깁니다. 그런데 "최근 일주일 장비별 점검 건수는?"이나 "지금 재고는?"처럼 정확한 조회가 필요한 질문은 기사 검색으로 풀기 어렵습니다. 다음 구간에서는 이런 정확한 조회를 코드에 맡기고, 그 함수를 모델이 도구로 부르는 방식을 봅니다.

## 16쪽 · S16 · data-skill steps

- 화면: 도구(Tool) 호출 순서 모델은 도구 호출을 요청하고, 실행은 프로그램이 합니다. 프로그램이 도구의 이름·설명·입력 형식을 알려 주면 모델은 부를 도구 이름을 담은 호출 요청을 돌려줍니다. @tool은 docstring을 도구 설명으로 쓰므로 설명이 모호하면 도구를 잘못 고릅니다. 이번 도구는 인자가 없어 모델은 '부를지 말지'만 정합니다. ① 프로그램 도구 알려주기 이름·설명·형식 ② 모델 호출 요청 tool_calls ③ 프로그램 실행과 반환 조회 결과 ④ 모델 결과로 응답 답변 또는 다시 ②로 ④에서 도구 호출이 더 없으면 답하고 끝냅니다 · 더 있으면 ②로 돌아가 반복합니다 @tool # 교육용 가상 함수 · 인자 없음 def equipment_status() -> list: """장비별 현재 위치와 진행 공정""" 출처: LangChain Tools · OpenAI Function calling 가이드 · 코드는 개념 예시
- 노트: "모델이 도구를 쓴다"는 말은 모델이 Python 함수를 자기 안에서 실행한다는 뜻이 아닙니다. 화면 네 카드의 위쪽 라벨은 그 단계를 누가 하는지, 카드 아래 작은 줄은 각 단계에서 오가는 내용입니다. LangChain 코드에서는 각 단계를 도구 스키마, tool_calls, ToolMessage, AIMessage라는 이름으로 부릅니다. 프로그램이 도구 스키마를 알려 주면 모델은 tool_calls에 도구 이름을 담아 요청만 하고, 실제 함수나 SQL은 프로그램이 실행해 결과를 ToolMessage로 돌려주며, 모델은 그 결과를 보고 답하거나 도구가 더 필요하면 다시 ②로 돌아가 요청합니다. 도구 호출이 더 없을 때 답하고 끝나는 것이 이 반복의 종료 조건이고, 오후에 볼 Claude Code도 같은 반복 구조입니다. 아래 코드처럼 @tool은 함수 이름, docstring, 타입 힌트로 도구 설명을 만들기 때문에 docstring은 동료에게 설명하듯 써야 하고, 이번 실습의 도구는 인자가 없어 모델이 정하는 것은 이 도구를 부를지 말지뿐입니다. 도구 호출은 모델의 '행동'이고, 그 권한과 부작용은 실행하는 프로그램 쪽에서 책임집니다.

Deep Agents는 그 위에 계획, 파일 공간, 하위 작업 위임을 미리 묶어 둔 하네스로, 여러 단계로 이어지는 긴 작업에 맞춰져 있습니다. 예제 코드 길이가 다르다고 성능이 다른 것은 아니며, 같은 과제로 비교한 결과가 아니면 성능 비교로 읽지 않습니다. 여러 Agent를 감독자형이나 넘겨주기형으로 나누는 방식도 있는데, 이것 역시 Agent 하나로 충분한지 먼저 확인한 뒤 고릅니다. ## 48쪽 · A08 · data-skill steps

- 화면: 부록 · Agentic RAG 검색 결과를 평가해 부족하면 질문을 고쳐 다시 찾습니다. 앞의 RAG 구간에서 본 '검색이 틀렸나' 확인을 그래프에 넣은 구조입니다. 모델이 문서마다 관련성을 yes/no로 매기고, 그 결과로 경로가 갈립니다. 판정마다 호출이 늘어 재시도 횟수를 제한합니다. 검색 retrieve → 관련성 평가 문서별 yes/no → yes 답변 생성 generate ↓ no 질문 재작성 다시 검색으로 · 횟수 제한 개념 예시 관련성 판정 스키마 · 교육용 축약(일부 줄 생략) class GradeDocuments(BaseModel): score: Literal["yes", "no"] grader = model.with_structured_output( GradeDocuments) grade = grader.invoke(prompt).score 출처: LangGraph Agentic RAG 문서 · Lewis et al. 2020
- 노트: 앞의 RAG 구간에서 답이 틀리면 검색이 틀렸는지, 가져온 자료를 잘못 설명했는지부터 나눠 보자고 했는데, Agentic RAG는 그 판단의 일부를 그래프 안에 넣은 구조입니다. 화면 왼쪽 그림처럼 검색한 뒤 모델이 문서마다 질문과 관련 있는지 yes나 no로 판정하고, 관련 문서가 있으면 답변을 만들고 없으면 질문을 고쳐 다시 검색합니다. 오른쪽 코드는 그 판정을 정해진 형식으로 받도록 yes와 no 두 값만 허용하는 스키마를 모델에 연결하는 부분을 교육용으로 줄인 것입니다. 이 그림에서 모델이 하는 일은 관련성 판정이고, 어느 길로 갈지는 그 결과를 받은 조건부 Edge가 정한다는 점도 봐 두세요. 같은 계열인 Corrective RAG는 근거가 부족하면 웹 검색으로 보완하고, Self-RAG는 답변이 근거에 맞는지까지 평가하며, Adaptive RAG는 질문에 따라 검색을 안 할지, 한 번 할지, 여러 번 할지를 먼저 고르는데, 사내망에서는 웹 검색 자체를 쓸 수 없을 수도 있습니다. 판정 한 번마다 모델 호출이 늘어 시간과 비용이 커지므로 재검색 횟수에 상한을 두고, 상한에 닿으면 억지로 답하지 않고 근거를 찾지 못했다고 알리게 합니다. 평가 단계를 넣었다고 환각이 사라지는 것은 아니니 근거 확인은 계속 필요합니다. 오늘 실습한 기본 RAG로 충분한지부터 확인하세요.

## 49쪽 · A09 · data-skill split

- 화면: 부록 · 하네스와 Deep Agents 하네스는 모델에 도구·기억·맥락을 묶는 실행 틀입니다. Deep Agents는 LangGraph 위에 계획·파일·위임 등을 미리 묶은 하네스입니다. Claude Code도 구현은 다르지만 같은 역할의 실행 틀입니다. 짧은 도구 호출이면 create_agent로 충분합니다. 하네스 · 모델을 둘러싼 실행 틀 모델 Tools 외부 기능 Memory 상태·저장소 Context 지침·규칙 Deep Agents가 미리 묶은 것 작업 계획 파일 도구 긴 출력 보관 하위 작업 개념 예시 create_deep_agent 인자 · 교육용 축약(값 생략) agent = create_deep_agent( model=..., tools=[...], subagents=[...], skills=[...], backend=..., interrupt_on={...}, ) 출처: LangChain Concepts(Agent harnesses: Deep Agents)
- 노트: 오후 실습에서 Claude Code가 파일을 읽고, 계획을 세우고, 명령을 실행하는 모습을 보셨는데, 이것은 모델 혼자 하는 일이 아니라 모델을 둘러싼 실행 틀이 해 주는 일이고, 이 틀을 하네스라고 부릅니다. 화면 왼쪽 그림처럼 하네스는 모델에 외부 기능을 부르는 Tools, 대화와 기록을 남기는 Memory, 지침과 규칙을 담는 Context를 묶습니다. Memory는 대화 중 상태를 저장하는 체크포인터와 대화를 넘어 남기는 저장소로 나뉘고, 하네스에는 이 셋 외에도 모델 호출 앞뒤에서 로그를 남기거나 가드레일을 거는 미들웨어가 들어갑니다. Deep Agents는 LangGraph 위에 작업 계획 목록, 허용된 경로 안의 파일 도구, 긴 출력을 파일로 넘기는 오프로딩, 하위 작업 위임을 미리 묶어 둔 하네스이고, 오른쪽 코드는 그 설정의 인자 이름만 보여 주며 값은 생략했습니다. Claude Code도 하네스라고 했지만 LangGraph나 Deep Agents로 만든 것은 아니고, 모델을 둘러싼 실행 틀이라는 역할이 같다는 뜻입니다. 다음 장에서 볼 사내 배포 패키지 예시도 이런 구성으로 만든 참고 예시입니다. 다만 도구 몇 개를 짧게 호출하는 작업이라면 create_agent로 충분하고, 하네스 기능은 긴 작업, 파일 작업, 사람 승인 같은 요구가 생길 때 고르면 됩니다. 인자 이름은 설치 판본에 따라 달라질 수 있으니 공식 문서에서 확인하세요.

## 50쪽 · A10 · data-skill steps

- 화면: 부록 · 사람 승인(HITL) 되돌리기 어려운 도구 실행 전에 멈추고 사람의 결정으로 재개합니다. interrupt()로 멈추고 Command(resume)로 사람의 결정을 받아 이어갑니다. 멈춘 상태를 저장할 체크포인터가 필요합니다. CLAUDE.md나 프롬프트의 '하지 마' 문장은 이것을 대신하지 못합니다. 도구 호출 모델이 요청 → 멈춤 interrupt() → 사람 결정 resume로 재개 ↓ 승인 도구 실행 거부 사유를 모델에 지정한 도구만 멈춤 · 결과는 다시 모델로 · 개념 예시 사내 배포 패키지 예시 화면의 승인 카드 · 실행할 명령과 승인·거부 버튼 · 수강생 실습 화면 아님 출처: LangGraph Human-in-the-loop 문서
- 노트: 삭제, 셸 실행, 외부 시스템 변경처럼 되돌리기 어려운 행동은 모델이 요청하더라도 사람이 한 번 보고 결정하게 하는 것이 안전합니다. 화면 왼쪽 그림처럼 모델이 도구 호출을 요청하면 interrupt()로 그래프를 멈추고, 사람이 승인하면 도구를 실행하고, 거부하면 그 사유를 모델에게 돌려줍니다. 사람의 결정은 Command(resume)로 전달해 멈춘 곳부터 이어가는데, 멈춘 상태를 저장해 둘 체크포인터가 있어야 하고, 저장된 상태는 나중에 조회해 어느 시점에서 멈췄는지 확인할 수도 있습니다. 앞 장 코드의 interrupt_on처럼 Deep Agents에서는 어떤 도구 앞에서 멈출지 설정으로 선언만 해도 같은 효과를 냅니다. 오른쪽 화면은 사내 배포 패키지 예시로, 셸 명령을 실행하기 전에 도구 이름과 명령을 보여 주고 승인과 거부를 받는 장면입니다. 수강생 실습 화면은 아니고, 승인 카드 부분만 잘라 보여 드립니다. 오후 실습에서 Claude Code가 파일 수정이나 명령 실행 전에 승인을 요청했다면 그것도 같은 발상의 장치이고, CLAUDE.md나 프롬프트에 "하지 마"라고 적는 문장은 이런 멈춤 장치를 대신하지 못합니다.
