## S10 · RAG의 기본 구조

- data-skill: `steps` (`.steps.row` 가로 3단계 권장)
- eyebrow: `B2` · `외부 근거와 기사 RAG`
- 제목: RAG의 기본 구조
- 단계 (단계 위 작은 라벨로 시점 구분: 1 = `미리 준비`, 2·3 = `질문할 때`):
  1. 자료 준비와 분할 — 본문을 확인하고 찾기 좋은 단위로 나눔
  2. 질문에 맞는 근거 검색 — 질문과 관련된 조각을 골라냄
  3. 근거를 사용한 답변 — 찾은 근거를 질문과 함께 모델에 전달
- 보조 문장(callout): 임베딩·Vector DB는 검색 방법 중 하나 · 모델을 다시 학습시키지 않음
- 출처: Lewis et al. 2020 · LangChain Retrieval 가이드
- 발표자 노트: RAG는 검색한 자료를 이번 답변을 만들 때 사용하는 방식입니다. 자료를 나누는 이유는 긴 문서 전체가 아니라 질문에 필요한 부분을 찾기 위해서입니다. 임베딩은 내용을 숫자 표현으로 바꾸는 과정이고, Vector DB는 그 표현과 원문을 보관하고 검색하는 저장소인데, 키워드 검색처럼 다른 방법도 있어 항상 필수는 아닙니다. 그리고 RAG는 모델 가중치를 바꾸는 학습이 아니므로, 다음 질문에서 그 자료를 모델이 기억하는 것도 아닙니다. 기사 한 편 전체를 요약하는 것과 질문에 맞는 근거를 찾아 답하는 것의 차이를 한 문장으로 말해 볼까요?
- 체크리스트 대조: 2번 해당(핵심 장면). callout과 노트에 "현재 답변에 이용·학습 아님"을 명시. 조사정리 5절 "URL 하나 전체 요약=항상 RAG Agent" 오해를 노트 질문으로 구분. 3번: 이 장면에서 Agent라는 말을 쓰지 않음.

## S12 · LangChain의 역할

- data-skill: `compare` (2열, 각 열에 코드 카드 포함)
- eyebrow: `B2` · `외부 근거와 기사 RAG`
- 제목: LangChain의 역할
- 보조 문장(scene-subtitle): 같은 작업: 근거와 질문을 담은 prompt로 답변 받기
- 열:
  - 열 1 — 작은 라벨: 직접 호출 / 열 제목: SDK
    - 코드 카드 (개념 예시, 6줄):
      ```python
      from openai import OpenAI
      client = OpenAI(base_url=BASE_URL)
      msgs = [{"role": "user", "content": prompt}]
      res = client.chat.completions.create(
          model=MODEL, messages=msgs)
      print(res.choices[0].message.content)
      ```
    - 요청·응답 형식을 직접 다룸
    - 단순 호출이면 이것으로 충분
  - 열 2 (**핵심 열, `is-accent`**, 이번 실습에서 사용) — 작은 라벨: 프레임워크 / 열 제목: LangChain
    - 코드 카드 (개념 예시, 4줄):
      ```python
      from langchain_openai import ChatOpenAI
      llm = ChatOpenAI(model=MODEL,
                 base_url=BASE_URL)
      res = llm.invoke(prompt)
      print(res.content)
      ```
    - 검색기·도구도 같은 방식으로 연결
    - 모델 성능을 높여 주지는 않음
    - 열 메모: 코드 길이 차이는 성능 차이가 아님
- 출처: LangChain Overview · LangChain Models 문서 · OpenAI Python SDK README
- 발표자 노트: 두 코드는 같은 일을 합니다. 근거와 질문을 담은 prompt를 모델에 보내고 답을 받습니다. 단순 호출 하나라면 왼쪽처럼 SDK로 충분하고, LangChain이 꼭 필요한 것은 아닙니다. LangChain의 장점은 모델, 메시지, 검색기, 도구를 같은 방식으로 연결하게 해 준다는 데 있고, 모델을 더 똑똑하게 만들어 주지는 않습니다. 이번 실습에서는 검색 결과와 모델 호출을 잇는 부분에 집중하고, LangGraph나 Deep Agents 같은 다음 단계는 필요할 때 고르면 되므로 부록 A03에만 두었습니다. 실습 코드에서 질문, 검색 결과, 모델 응답이 각각 어디 있는지 짚어 보세요.
- 제작 메모: 코드는 실제 실습 코드가 아닌 표준 예시다(ChatOpenAI의 `base_url`, `invoke`, OpenAI SDK `chat.completions.create` 사용법은 Context7 공식 문서로 확인). `api_key`는 환경변수에서 읽는 기본 동작을 전제로 화면에 쓰지 않는다. compare 열 안에 `.code-card`를 넣는 배치는 UI 담당 확인 대상이다. 공간이 부족하면 열마다 항목을 1개로 줄인다.
- 체크리스트 대조: 10번 해당. 노트에서 "LangChain→LangGraph→Deep Agents를 순서대로 모두 배울 필요 없음"을 부록 안내로 처리. 13번: `MODEL`, `BASE_URL`만 사용. 초안의 기능 나열(모델 호출·검색 결과 연결·도구 인터페이스)을 같은 작업 비교로 바꿔 코드 길이를 성능 비교로 오해하지 않게 열 메모 추가(출처목록 5절 06_comparison 주의사항).
- 수정 기록(2026-09-14): UI 축소 B2-1 반영 — SDK 코드를 `msgs` 변수로 나눈 6줄(한 줄 44자 이하)로 교체. 호출 동작은 같음. 호출 줄 `span.hl` 강조 유지 요청은 UI 담당 사항.
- 자산 대기: 없음 (실제 실습 코드로 바꿀지는 보류 목록 참고)

- 체크리스트 대조: 2번 해당. 검색 실패와 설명(생성) 실패를 callout으로 분리해 "RAG를 붙이면 끝" 오해를 차단. 12번: 수치 예시 없음. 초안 항목 "근거에 있는 내용 / 추가 확인이 필요한 내용"을 열 제목 2단어(근거에 있음 / 근거 밖)로 줄이고 판단 기준을 항목으로 풀었다.
