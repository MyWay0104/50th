## S04 · LLM의 응답 생성

- data-skill: `steps` (`.steps.row` 가로 3단계 권장)
- eyebrow: `B1` · `LLM 원리와 첫 호출`
- 제목: LLM의 응답 생성
- 단계:
  1. 토큰으로 나누기 — 문장을 모델의 처리 단위로 분할
  2. 다음 토큰 분포 계산 — 지금까지의 문맥으로 후보별 가능성 계산
  3. 선택하고 반복 — 하나를 골라 붙이고 다시 계산
- 예시 줄 (`.chip-row`, 배지 "개념 예시"): `회의` `내용을` `세` `줄로` → 다음 후보: `요약` `정리` `…`
  - 예시 캡션: 실제 토큰 분할은 모델마다 다름 · 확률 수치는 표시하지 않음
- 보조 문장(callout): 학습은 매개변수를 바꾸고, 보통의 호출은 학습된 모델로 계산만 한다
- 출처: Vaswani et al. 2017 · Ouyang et al. 2022 (지시 수행 학습)
- 발표자 노트: LLM은 입력을 토큰이라는 단위로 나누고, 지금까지의 문맥으로 다음 토큰 후보들의 가능성을 계산해 하나를 고르는 과정을 반복합니다. 토큰은 단어 하나와 항상 같지 않고, 나누는 방식은 모델마다 다릅니다. 학습 단계에서는 모델 매개변수를 바꾸지만, 오늘 우리가 하는 API 호출은 이미 학습된 모델로 결과를 계산할 뿐입니다. 그러면 질문을 한 번 더 보내면 모델이 바로 재학습될까요? 한 분만 짧게 답해 주세요.
- 체크리스트 대조: 2번 관련(질문 전송·자료 제공≠학습) 통과. callout으로 학습과 추론을 구분. 12번 해당: 예시에 확률 숫자를 넣지 않음(측정값처럼 보이지 않게).
- 수정 기록(2026-09-14): W4 반영 — 예시 캡션에서 "토크나이저"를 빼 화면의 새 용어를 4개에서 3개로 줄임.
- 자산 대기: 없음 (수업 모델의 실제 토크나이저 결과를 쓰려면 보류 목록 참고)

## S05 · Attention과 문맥

- data-skill: `split`
- eyebrow: `B1` · `LLM 원리와 첫 호출`
- 제목: Attention과 문맥
- 시각 쪽 (개념도 `.dg`, 두 줄)
  - 성격 배지: 개념 예시
  - 패널 제목: 같은 '배', 다른 문맥
  - 1행: 상자 `디저트로 배를 먹었다` → 강조 상자 `배 = 과일`
  - 2행: 상자 `항구에서 배를 탔다` → 강조 상자 `배 = 선박`
  - 캡션: 주변 단어가 표현에 반영되는 개념도 · 측정값 아님
- 해석 항목:
  1. 같은 표현도 문맥에 따라 다름
  2. 다른 위치의 정보를 반영하는 계산
  3. 데이터·규모·학습 방법으로 활용 확장
- 출처: Vaswani et al. 2017 · Ouyang et al. 2022
- 발표자 노트: 같은 '배'라도 '먹었다'와 함께 오면 과일, '탔다'와 함께 오면 선박으로 읽힙니다. Attention은 각 위치의 표현을 만들 때 다른 위치의 정보를 얼마나 반영할지 계산하는 장치이고, 이 값은 입력마다 새로 계산되므로 학습된 모델 매개변수와는 다릅니다. 참고로 원 논문은 번역용 encoder–decoder 구조였고, 오늘날 많은 생성 모델은 decoder 중심 구조를 씁니다. 데이터·규모·학습 방법이 발전하며 쓰임이 넓어졌지만, 이를 어느 순간의 특이점으로 단정하지는 않겠습니다. Q·K·V 계산이 궁금하신 분은 부록 A01을 참고하세요.
- 체크리스트 대조: 9번 해당. 노트에서 원 논문 encoder–decoder와 현재 decoder 중심 생성 모델을 구분. 조사정리 5절 "특이점" 표현 방지를 위해 초안 "여러 작업으로 확장된 언어 모델"을 "데이터·규모·학습 방법으로 활용 확장"으로 수정. 12번 해당: attention 가중치 수치·열지도를 넣지 않음.
- 자산 대기: 없음

API는 프로그램끼리 요청과 응답을 주고받는 약속이고, SDK는 그 호출 코드를 편하게 쓰게 돕는 Python 도구입니다. 코드에 OpenAI라는 이름이 있어도 실제 요청이 가는 곳은 base_url에 적은 주소이고, 호환 API라고 해서 모든 옵션과 도구 호출이 똑같이 지원되는 것은 아닙니다. 코드는 내 PC에서 돌아도 모델 계산은 서버에서 일어난다는 점도 기억해 두세요. 코드 첫 줄의 langchain은 10시 구간에서 다루니, 지금은 model과 base_url 두 줄만 보세요. 이제 실습 코드에서 모델 이름과 요청 주소를 지정하는 위치를 같이 보겠습니다.

Attention은 각 위치의 표현을 만들 때 다른 위치의 정보를 얼마나 반영할지 계산하는 장치이고, 이 값은 입력마다 새로 계산되므로 학습된 모델 매개변수와는 다릅니다. 화면 오른쪽은 원 논문의 전체 구조 그림으로, 왼쪽 묶음이 입력을 읽는 encoder, 오른쪽 묶음이 출력을 만드는 decoder이고, 주황색 Multi-Head Attention 칸이 방금 말한 계산을 하는 곳입니다. 원 논문은 번역용 encoder–decoder 구조였고, 오늘날 많은 생성 모델은 decoder 중심 구조를 씁니다. 데이터·규모·학습 방법이 발전하며 쓰임이 넓어졌지만, 이를 어느 한순간에 갑자기 달라진 일로 단정하지는 않겠습니다.
