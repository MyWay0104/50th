## 1. 목표와 기대 성과 (plan-task의 description)

### 1-1. 문제

사용자 지적: **"각 슬라이드 제목부터 비유적 표현이 들어가서 정확하게 무엇을 배우는 건지 알기 힘들다."**

지금 덱은 제목이 "책 — 찾아보며 답합니다, RAG", "조종 — 두뇌가 손발을 조종합니다, Agent" 처럼 비유가 앞에 온다. 슬라이드 목록만 훑으면 학습 내용이 흐릿하고 나중에 다시 찾아볼 때도 불리하다.

### 1-2. 하려는 것

덱 v0.6(66장)의 **비유 표현을 전부 걷어내고 전문용어만 남긴 v0.7을 만든다.** 같은 topic 폴더를 그대로 갱신한다(새 폴더를 만들지 않는다).

### 1-3. 기대 성과

1. 비유 낱말(두뇌 · 책 · 손발 · 조종 · 내 PC의 에이전트 · 열쇠 · 문 · 정거장)이 화면과 발표자 노트에서 **0건**.
2. 진행 축이 **LLM → RAG → Tool → Agent → Coding Agent → 적용** 로 통일되어 제목 · 띠 · 칩이 같은 낱말을 쓴다.
3. 화면 글자 총량이 **v0.6보다 줄어든다**(늘리지 않고 덜 중요한 문장을 지운 결과).
4. QA 게이트 5단계 통과, 넘침 · 겹침 0.
5. 핵심 흐름(개념-실습 짝 · 완료 조건 · 안전 문장 · 확인 질문 · 의도적 에러)이 v0.6과 같은 개수로 남는다.

## 3. 용어 사전 (확정 · 모든 작업의 기준)

### 3-1. 진행 축 6칸

```
LLM  →  RAG  →  Tool  →  Agent  →  Coding Agent  →  적용
```

띠 라벨 아래 작은 글씨(`dg-sub`)는 다음으로 통일한다. **띠가 있는 9개 장면(G01 · D01~D07 · G02)이 모두 같아야 한다.**

| 칸 | 라벨 | 작은 글씨 |
|---|---|---|
| 1 | LLM | 모델 호출 |
| 2 | RAG | 자료 검색 |
| 3 | Tool | 도구 호출 |
| 4 | Agent | 반복 판단 |
| 5 | Coding Agent | Claude Code |
| 6 | 적용 | 내 업무 |

### 3-2. 아이콘 — **그대로 유지** (사용자 지시)

`brain` · `book-open` · `hand` · `joystick` · `laptop` · `rocket` · `key` · `door-open` 파일을 바꾸지 않는다. 글자만 전문용어로 바뀌고 아이콘은 시각적 표시로 남는다.

단 **아이콘의 `alt` 대체 글자에는 비유가 남는다**("두뇌 아이콘" · "손발 아이콘" · "열쇠 아이콘" 등). 화면에는 안 보이지만 검증 grep에 걸리고 스크린 리더가 읽는다. 덱 전체 일괄 치환으로 처리한다(9절 알려진 문제 ②).

## 5. 제약 조건 (plan-task의 requirements)

### 5-1. 문장 줄이기 원칙 (사용자 지시)

전문용어는 비유보다 길다. **문장을 길게 늘어뜨리지 말고 덜 중요한 문장을 과감히 지운다.** 다만 핵심 흐름이 깨지면 지우지 않는다.

우선순위:

| 순위 | 방법 |
|---:|---|
| 1 | **덜 중요한 문장 삭제** |
| 2 | 남긴 문장 압축(수식어 제거, 두 문장 → 한 문장) |
| 3 | 장면 전용 CSS로 흡수(글자 24px 아래로는 내리지 않는다) |
| 4 | 화면 컴포넌트 재구성 |

먼저 지울 것: ① **비유를 풀어 주던 보조 문장**(비유가 사라지면 불필요) ② 한 줄 요지와 겹치는 설명문 둘째·셋째 문장 ③ 도식이 이미 말하는 캡션 ④ 노트에서 화면 글자를 되풀이하는 부분.

### 5-2. 지우면 안 되는 것 (핵심 흐름)

- 실습 안내판의 **개념 칩 줄**(소단계 ↔ 개념 짝)
- **완료 조건** · **막히면**
- **안전 문장**(3-6절)
- 전환 장면(T01~T03)의 세 열 구조
- **확인 질문**과 그 답이 나오는 짝
- 의도적 에러의 예고와 디브리핑(0으로 나누기 · 401)
- 출처 줄 · 자리표시(`[IMG-PLACEHOLDER · P-…]`)
- G02의 중심 메시지("LLM에게 맡길 일과 코드·데이터·사람이 책임질 일을 구분하면…") — 글자 그대로
- ROADMAP2 확정 사실(R2-1~R2-21)을 담은 문장

### 5-3. 기술 제약

- 덱 수정은 **`scripts/deck/apply_table.py`** 로 한다. 서브에이전트는 표(JSONL)만 만들고 `index.html`을 직접 고치지 않는다.
- CSS는 `index.html`의 `ROADMAP2-PATCH` 구간을 직접 고치지 말고 `_workspace/roadmap2/slide_ui/0N_*.css`를 고친 뒤 `apply_css_patch.py`로 다시 붙인다.
- 인라인 `style` · hex 색 · `<br>` · CSS에 없는 클래스 금지.
- 하우스 룰(`deck-rules.json`): 화면 존댓말 · 시각과 분 표기 금지(G01 · G03 예외) · 사내 고유명 금지 · 출처는 공식 문서와 논문만 · 장면마다 시각 요소 1개 이상.
- 서브에이전트 동시 실행 3~4개. 장면 단위로 덧붙여 저장(중단 대비).
- **export와 git 커밋은 사용자 지시가 있을 때만.**

### 5-5. 화면 배치 기준 (2026-09-18 사용자 지시 · 전 슬라이드)

1. **텍스트가 한쪽으로 몰리지 않게 한다.** 좌우 열의 무게가 한쪽으로 쏠리거나, 한 열만 꽉 차고 다른 열이 비는 배치를 만들지 않는다.
2. **기본은 균형 잡힌 중앙 정렬.** 상자 안 내용은 상하좌우 가운데(v0.6에서 이미 적용), 그리고 **장면 전체의 무게 중심도 가운데**에 오게 한다. 글을 지운 뒤 생긴 빈 자리 때문에 남은 내용이 위로 쏠리면 세로 가운데로 다시 맞춘다.
3. **컴포넌트끼리 다닥다닥 붙지 않게 한다.** 상자·칩·도식 사이에 숨 쉴 여백을 둔다. 글을 지워 생긴 여유는 **글자를 키우는 데 쓰지 말고 간격을 넓히는 데 쓴다.**
4. 이 기준은 `slide_ui_designer`가 T6(넘침 수습·재구성)과 T8(시각 검수)에서 책임진다.

## 13. 치환 표 형식 (`scripts/deck/apply_table.py`)

장면 하나가 한 줄이다. `--kind copy` 로 적용한다.

```json
{"sid": "S04", "title": "새 제목", "source": "출처: …", "replace": [{"where": "screen", "old": "정확히 한 번 나오는 원문", "new": "바꿀 글"}]}
```

- `title` · `source` 는 **생략하거나 `null` 이면 그대로 둔다.** `source` 가 `""` 면 출처 줄을 지운다.
- `old` 는 **그 장면의 해당 부분(screen 또는 note)에서 정확히 한 번** 나와야 한다. 0회나 2회면 그 항목만 건너뛰고 보고한다.
- **문장 삭제는 `"new": ""`.** 문장 앞뒤 공백까지 `old` 에 넣어 빈 줄이 남지 않게 한다.
- 요소를 통째로 지우거나 구조를 바꾸는 것은 **`--kind visual`** 로 따로 다룬다.
- 적용 전 반드시 `--dry` 로 "못 찾음 0" 을 확인한다.
