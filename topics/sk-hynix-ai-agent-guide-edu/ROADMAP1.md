### 1-4. 교안 3권에서 가져올 교수 리듬

4일 교안은 절마다 "왜 필요한가 → 개념 정의 → 코드 → 시각화 → 핵심 요약"으로 닫는다. 하루 덱에서는 이를 **[한계 1장 → 개념+도식 1~2장 → 실습 안내판 1장]**의 3~4장 리듬으로 접는다. "왜"는 직전 구간 마지막 장의 마지막 문장과 다음 개념 장 노트의 첫 질문으로, "요약"은 실습 완료 조건("바꾼 값과 차이를 한 문장으로")을 수강생이 말하는 것으로 대신한다. agent-handbook의 **결핍→해결 서사**(먼저 못 하는 장면을 보여 주고 해법 도입)를 각 전환점에 쓴다.

## 2. 설계

### 2-1. 재구성 원칙 (7개)

1. **개념-실습 짝**: 실습 소단계마다 직전 개념 하나를 "개념 칩"으로 붙인다(예: `② 역할 · system`). 짝이 없는 개념은 부록으로, 짝이 없는 실습은 관찰 포인트를 만든다.
2. **실습 직전 새 용어 3개 이하**. 넘치면 노트로 내리거나 부록으로 보낸다.
3. **전환점마다 "왜 다음이 필요한가"**: 단순 호출의 한계 → RAG / RAG의 한계(정확한 조회) → Tool / 도구 붙인 함수 → 화면 / 내가 도구를 붙였다 → 도구가 이미 붙은 Agent(Claude Code)에게 맡긴다.
4. **관찰 가능성**: 실습마다 눈으로 보는 변화를 하나 둔다(system 한 줄 바꿔 답 변화, temperature 3회, chunk_size 바꿔 조각 수, 도구 없는 질문에서 tool_calls가 비는지).
5. **오해 예방 명칭**: "AI 없는 RAG" → "찾아서 읽기(검색만)", "URL 요약 = RAG" → "외부 문서 기반 요약"(질문에 맞는 조각을 골라 넘길 때 RAG라 부른다), "SQL Agent" → "조회 도구를 붙인 Workflow"(Agent와의 경계는 S17에서 확인).
6. **시간 압박 없음**: 시각은 G01의 시작·점심·종료뿐. 실습 안내판은 순서 번호만. 강사 참고용 분 배분은 이 문서 2-3절에만 둔다.
7. **하우스 룰 유지**: 사내 주소·모델명·키·사내 SDK 이름은 역할 이름으로, 존댓말, 출처는 공식 문서·논문만, 장면마다 시각 요소 1개, 교안 3권은 화면 출처로 쓰지 않는다.

지키는 방법: ① 선택 과제 M01(강제 아님, 주제가 없는 사람용) ② S25 참여 활동 유지 ③ S28 4단계를 방향 ② 시연 캡처의 라벨로 ④ S31 3분법을 S43에 통합 ⑤ S21·S22 연결 문장을 "오후 시연과 선택 과제의 대상"으로 정확히. 전원이 겪지는 않으므로 방향 ② 시연(S28)이 성과 3·4의 공통 근거가 된다.

## 5. 테스트 방법

1. 4절 QA 게이트 통과. 시간 표기 검사에서 G01·G03 외에 걸리는 장면 0건.
2. 검토자 판정표: llm-professional의 실습 단계별 표에서 "보강 필요" 0건, lecture_expert의 9항목에서 "수정 필요" 0건(보류는 사용자 답변으로 해소).
3. 실습 안내판 5장(실습 1~5) 각각에 소단계 ≤5, 소단계마다 개념 칩 1개, 완료 조건 1개, 막힘 대체 경로 1개.
