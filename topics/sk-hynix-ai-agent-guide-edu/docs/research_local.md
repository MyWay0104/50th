## 4. 강사가 함께 제공하면 좋은 15개 후보

아래의 `제안`은 자료를 바탕으로 강의에 맞게 재구성한 교육적 판단이다. API 사양의 현재 정확성은 별도 공식자료 확인이 필요하다.

### 1) 모델·서버·API·라이브러리는 서로 다른 층이다 — 필수

- **자료 사실:** N0 셀 6은 `ChatOpenAI(model=..., base_url=..., api_key=...)`를 분리해 전달한다.
- **전달할 내용:** 모델은 사용할 LLM, 서버는 그것을 실행·제공하는 시스템, API는 요청·응답 통로, LangChain은 호출과 연결을 돕는 코드 도구라는 층을 나눈다. 사내 vLLM API에 연결하는 코드를 이 그림에 직접 붙인다.
- **좋은 예:** 동일한 Python 호출에서 모델명과 서버 주소가 왜 별도인지 색상으로 표시한다.
- **매핑:** 오전 첫 API 호출 직전, PDF 1장 + HTML 환경 설정 + ZIP 공통 설정 파일.
- **출처:** N0 `0.2 모델 초기화`(셀 5~6), N1 `1.1 환경 설정`(셀 3).

### 2) 프롬프트는 문장뿐 아니라 역할과 대화 기록의 묶음이다 — 필수

- **자료 사실:** N1은 System/Human/AI 메시지, 같은 질문에 서로 다른 설명 지침, 문자열·객체·딕셔너리 입력을 비교한다.
- **전달할 내용:** 단순 페르소나 지정에 머물지 않고 목표·입력·제약·출력 형식을 적는 방법을 보여준다. 규칙을 썼다고 응답의 사실성이 자동 보장되는 것은 아니라는 설명을 덧붙인다.
- **좋은 예:** 동일 기사에 대해 `핵심 3줄`, `공정 엔지니어에게 의미 있는 영향`, `근거 없는 내용은 모름으로 표시`를 요청한다.
- **매핑:** 오전 단순 호출→답변 확인.
- **출처:** N1 `1.2 메시지의 세 가지 역할`(셀 5), `1.3 시스템 메시지로 행동 제어`(셀 7~8).

### 3) temperature 실험에는 '같은 조건에서 여러 번'이라는 관찰 기준이 필요하다 — 필수 보충

- **자료 사실:** N1 셀 3은 temperature를 0.2로 설정할 뿐, 온도별 비교 실험이나 정답 평가를 제공하지 않는다.
- **제안:** 같은 프롬프트·모델·입력으로 여러 번 실행하고, 답의 다양성과 근거 정확성을 별도 축으로 기록한다. `온도를 낮추면 사실이 된다`, `0이면 늘 똑같다` 같은 단정은 피하고 현재 사용 모델·서버 지원 범위를 공식자료/실측으로 확인한다.
- **좋은 예:** 요약 문체 비교와 단순 산술 정확도를 같은 표에 놓고 서로 다른 평가 항목임을 보여준다.
- **매핑:** 오전 temperature 실습과 RAG 필요성 사이.
- **출처:** N1 `1.1 환경 설정` 셀 3. 실험 방식은 교육 제안이며 원본에 없는 추가 내용.

### 4) 단순 호출→정해진 흐름→도구를 고르는 Agent를 구분한다 — 필수

- **자료 사실:** N4는 대문자 변환→단어 수 계산을 정해진 순서로 실행한다. N2는 질문→모델의 도구 선택→도구 결과→반복/최종 답변 루프를 설명한다.
- **전달할 내용:** 단계가 미리 정해졌는지, 모델이 다음 행동을 선택하는지를 기준으로 workflow와 agent를 비교하면 프레임워크 이름 없이도 이해하기 쉽다. 한 번의 LLM 호출이나 Tool 추가 자체를 모두 자율 에이전트라고 부르는 혼동을 줄인다.
- **좋은 예:** `기사 가져오기→요약`과 `질문에 따라 기사검색/SQL 중 선택→결과 확인`을 나란히 표시한다.
- **매핑:** 오전 RAG 요약→Tool/Agent 소개 전환.
- **출처:** N2 `2.3 에이전트 생성 & 실행`(셀 7~10), N4 `4.3 2노드 그래프`(셀 7~8).

### 5) Tool은 모델의 말과 프로그램의 실제 실행을 연결한다 — 필수

- **자료 사실:** N2의 add/multiply, N7의 internet_search는 함수 설명과 타입 힌트를 도구 선택·입력 스키마에 활용한다.
- **전달할 내용:** LLM이 함수 이름·인자를 요청하고, Python 코드가 실행하며, 결과를 모델에 돌려주는 경계를 보여준다. 도구 설명에는 언제 쓰는지, 입력값과 제한, 결과 형식을 적는다.
- **좋은 예:** `6×7+10`을 말로 답하는 경우와 multiply→add 실행 기록을 비교한 뒤 SQL로 확장한다.
- **매핑:** 오전 SQL Tool 직전, PDF 루프 그림 + HTML 실행 기록 + ZIP 도구 함수.
- **출처:** N2 `2.2 도구 만들기`(셀 5~6), N7 `7.2 검색 도구 정의`(셀 5~6).

### 6) 외부 근거 추가와 외부 행동 실행의 목적을 나눠 설명한다 — 필수

- **자료 사실:** N7은 Tavily 검색결과를 가져와 요약한다. 문서 청킹·임베딩·벡터 검색 코드는 없다.
- **전달할 내용:** 모델이 모르는 정보를 보충하는 검색/검색증강과 계산·조회·작업을 수행하는 Tool은 구분하되 함께 사용할 수 있음을 보여준다. 웹검색 기반 검색증강도 가능하지만, `페이지 전체를 전달한 요약`, `질문 관련 부분을 검색한 뒤 답하기`, `모델이 검색 행동을 결정하기`를 구체적 처리 흐름으로 구별한다.
- **좋은 예:** 동일 Naver 기사에서 기사 전체 요약과 특정 질문에 필요한 부분 검색을 비교한다.
- **매핑:** 오전 RAG 정의→Naver 기사 실습.

## 5. 원본 문구를 그대로 슬라이드에 옮기기 전에 보정할 점

1. **프레임워크 비교를 성능 서열로 만들지 않는다.** N6의 'Deep Agents로 프로덕션급 에이전트'는 특정 SDK 도입만으로 운영 품질이 보장된다는 뜻으로 읽힐 수 있다. 제품의 필요한 기능을 기준으로 선택하도록 바꾼다.
2. **메모리/영구 저장 기본값을 단정하지 않는다.** N5의 내장 기능 표는 가능 기능과 기본 동작이 섞여 읽힐 수 있다. 실제 백엔드·체크포인터 설정을 확인한다.
3. **세 가지 최소 코드는 동등한 실험이 아니다.** N6 셀 4의 LangChain 예시는 add 도구가 있지만 LangGraph 예시는 모델 1회 호출, Deep Agents는 기본 하네스다. 같은 질문만으로 성능·효율을 비교했다고 말할 수 없다.
4. **노트북에 나온 모델명을 사내 모델명으로 간주하지 않는다.** 환경변수 지정과 `gpt-4.1`, `qwen3.5:4b` 하드코딩이 섞여 있다. 배포용 ZIP은 사내 실제 모델/주소 설정을 하나로 모아야 한다.
5. **스트리밍 설명과 실제 파라미터를 대조한다.** N3/N7 Markdown에 `stream(mode="updates")` 표현이 있지만 코드는 `stream_mode="updates"`를 사용한다. 최신 API 정확성은 설치 버전/공식 문서로 확인한다.
6. **N0 환경설정 문서와 코드 요구값이 다르다.** Markdown은 API 키를 중심으로 설명하지만 코드에서는 `OPENAI_MODEL`, `OPENAI_BASE_URL`도 필수로 검사한다. HTML/ZIP에 누락 없는 예시 환경파일이 필요하다.
7. **ToolMessage 필수 필드 설명을 공식자료로 확인한다.** N1 셀 5는 도구 이름까지 필수라고 서술한다. 이 서술의 현재 정확성은 확인 전이다.
8. **과거 운영 수치를 현재 성과로 인용하지 않는다.** B2의 글 수·이미지 수·빌드 페이지 수 등은 과거 대화 보고 기준이다. 강의에서 사용자 실제 성과를 수치로 제시하려면 현재 서비스/기록으로 재확인한다.
9. **관측 플랫폼 연동은 사내 허용된 환경을 기준으로 한다.** 노트북에 LangSmith/Langfuse 예시가 있다는 사실만으로 교육 환경에서 사용할 수 있다고 보지 않는다. 강의의 필수 내용은 단계별 기록이며 플랫폼 설치는 선택이다.

## 6. 추가 자료가 확보되면 우선 확인할 항목

- 실제 오전 HTML와 ZIP: 각 실습의 함수명, 화면, 정답 예시, 실행 순서, 패키지 버전, 사내 API 설정을 발표안에 정확히 매핑.
- 실제 Naver 요약 구현: 전체 본문 요약인지, 질문 기반 부분 검색인지, 임베딩/검색 저장소가 있는지, 모델이 검색 여부를 결정하는지.
- SQL Tool: 스키마 설명 전달 방식, 읽기 계정/조회 범위, 쿼리 검증, 결과 제한, 실패 복구, 어떤 모델의 tool calling을 사용하는지.
- Part Finder Agent 실제 개발 회고: 최초 설계와 나중에 수정한 구조를 익명화한 전후 그림, 사용자 피드백, 실제 실패 사례, 운영 지표. 현재 노트북에는 사례 근거 없음.
- 사내 Claude Code 설치 가이드: 현재 배포 경로·인증·프록시/네트워크·허용 MCP/도구·권한 기본값. 공개 공식문서만으로 회사 정책을 추정하지 않음.
- Obsidian 지적자산 사례: 공개 가능한 실제 기록 1~2개와 그 기록을 참고해 답변이 달라진 예시. 해당 로컬 경로에 문서가 없어 검증하지 못함.
