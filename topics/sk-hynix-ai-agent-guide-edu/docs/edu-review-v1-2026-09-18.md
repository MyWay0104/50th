## 1. 3줄 요약

1. 현재 덱은 오전을 "실습 1~4(호출 → 기사 통째 요약 → 인자 없는 조회 도구 → 화면 붙이기)"로 그리지만, 실습자료는 "01 환경 → 02 호출·체인 → 03 캐릭터 봇 → 04 검색 기반 QnA → 04b 계산 도구·데이터 직접 조회 → 05 Agent 루프"다. 55장 가운데 22장에 확정 사실(R2-2·3·4·5·6·7)과 어긋나는 문장이 있고, 가장 큰 끊김은 T03과 S17이 "손발 → 조종(Agent)"을 "도구 → 화면"과 "Workflow에 가깝다"로 닫아 서사 축의 정점이 사라진 것이다.
2. 실습자료의 핵심 요소 가운데 프롬프트 템플릿과 체인, 인자·bind_tools·한 질문 여러 번 호출, 0 나누기·401·열쇠 3종, Agent 루프·반복 상한·SQL 이스케이프, settings 연결·일일 한도, 기본 프롬프트 3종, 구현 방식 선택, 비유 축(두뇌·책·손발·조종·내 PC의 에이전트)이 덱에 없다. 반대로 Chroma·Milvus 비교(V02)와 실행 환경 네 층(S19)은 실습 근거가 없는 개념 확장이다.
3. 권고는 신설 6장(LAB01 · N01 · LAB03 · N02 · N03 · LAB07), 합침 2건(S09 → T01, S41+S42 → LAB08), 재작성 18장, 보강 15장, 유지 9장 → **본문 49장**(V02를 부록으로 내리면 48장, 부록 11장). 다만 새 구조로 셈하면 오전의 시간 수요가 배정을 넘는다(7절). 스킵 지정, 실습 분기, 사전 과제 범위 확인이 함께 필요하다.

## 11. 확인 필요 사항

### 11-A. 사용자(강사)에게 물을 것

1. **04b의 반복과 05의 Agent를 어떻게 구분해 말할 것인가.** 요약본 §실습05는 "Tool Calling은 한 번 호출"이라 하지만 §실습04b도 반복 루프이고 R2-3은 "한 질문에 여러 번 호출"로 확정했다. 기본 표현으로 "04b에서 손으로 돌려 본 반복이 Agent 루프의 가장 작은 모양이고, 05에서 이름을 붙이고 실제 데이터를 읽는 손발 · 멈춤 장치 · 화면을 더한다"를 써도 되는가.
2. S09를 T01에 합치는 안(−1장)에 동의하는가. 두 장이 같은 세 가지 한계를 연달아 말한다.
3. V02(FAISS · Chroma · Milvus)는 사용자 요청으로 넣은 장면이다. 본문에 두고 스킵 가능으로 표시할지, 부록으로 내릴지.
4. 오전 시간이 넘친다(7절). (가) 키 2종 발급과 `.env` 작성을 사전 과제에 넣을 수 있는가. (나) 시간이 밀릴 때 실습 04b의 직접 조회와 실습 05 콘솔판을 강사 시연으로 바꿔도 되는가. (다) 비상안으로 실습 05를 점심 뒤 첫 순서로 넘길 수 있는가.
5. 휴식 배분(오전 몇 번, 오후 몇 번). 7-1절 가정의 검증에 필요하다. 참고로 ROADMAP1 2-3절 배분표의 합이 같은 문서가 말하는 교육활동 시간과 맞지 않는다(7-2절).
6. E01 셋째 층의 화면 이름. "사내 추론 서버"(현재)와 "사내 게이트웨이"(실습 06) 가운데 하나로 통일해야 오후에 같은 그림으로 재등장시킬 수 있다. vLLM이라는 낱말을 화면에 둘지도 함께.
7. 일일 한도의 금액을 화면에 쓸지. 권고는 금액 없이 "일일 한도가 있습니다. 남은 한도는 사내 모델 운영 페이지에서 확인합니다."
8. 실습 07에서 여는 폴더가 오전 실습 폴더인가. "버그를 찾아줘"의 대상은 무엇인가. 제안: 실습 04b의 나누기 도구를 대상으로 하면 오전의 의도적 에러를 오후에 Claude Code가 찾아내는 서사가 된다.
9. S17의 위치. LAB05 앞(개념)과 뒤(디브리핑 겸 확인 질문) 가운데 권고는 뒤다. G02를 재작성해 축 띠를 얹는 안과 별도 장을 하나 더 만드는 안(본문 50장) 가운데 권고는 재작성이다.
10. 메시지 역할(system · user)을 N01에서 템플릿의 재료로 소개하고, L01은 페르소나 · format 장으로 바꿔 LAB03 앞에 두는 재편에 동의하는가.
11. "모델은 이번에 보낸 목록만 본다"는 원리 한 줄을 남겨도 되는가. R2-4가 지운 것은 긍정봇의 관찰과 복선이므로, 근거를 실습 04b의 결과 전달(ToolMessage)로 옮겨 S16과 S30에서만 쓰는 안이다.
12. 실습 03의 대화 루프는 안내판 소단계로 넣되 기억 여부는 관찰하지 않는다 — 맞는가.
13. 요약본의 "학습 지속" 뒤에 잘린 내용이 있는가. 실습 05 테스트 질문의 "펩"은 원문 오타인가(슬라이드에는 가상 장비 ID와 "팹"으로 쓸 예정).
14. G00 노트의 "후속 읽을거리"가 실습자료에 실제로 있는가. G01에 실습자료의 Part 1~4 표기를 그대로 써도 되는가(구간 코드 금지 규칙과는 다른 것으로 보았다).

### 11-B. 사내 확인 요청 (코드를 봐야 풀리는 것 — `docs/handoff-inhouse-claude-lab-check.md`에 넣을 항목)

1. **실습 04**: 검색해서 가져오는 조각 개수(벡터 저장 단계와 QnA 단계 각각), 점수가 거리인지 유사도인지(거리 방식을 따로 지정했는지), 인덱스를 파일로 저장하는지, retriever를 쓰는지, 기사 주소가 고정인지 입력인지, 저장 본문으로의 전환이 자동인지 수동인지, 수집 실패 때의 오류 모양.
2. **실습 04b**: Tool 없는 호출 단계에서 던지는 질문, 반복의 구현 방식(호출이 없을 때까지 도는 반복문인지), 0으로 나눌 때 프로그램이 멈추는지 오류가 모델에게 돌아가는지, 직접 조회 단계의 출력 모양, 401 때의 메시지.
3. **실습 05**: Agent의 구현 방식(손으로 짠 반복 / 기성 실행기 / create_agent 계열), 반복 상한이 콘솔판에도 있는지, 매 바퀴 기록의 모양, 조회 도구의 인자와 SQL 조립 · 이스케이프 방식(Text-to-SQL이 아님을 화면에 써도 되는지), 시스템 프롬프트 유무, '장비 메모리' 사이드바의 동작(R2-11), 대화 이력 유지 여부, 없는 장비 ID를 넣었을 때의 동작(M01 · S25 · S28의 "결과 없음 안내"가 이미 있는지).
4. **실습 02**: 첫 호출에서 토큰 사용량을 출력하는지, 코드에 공급사 이름이 보이는지.
5. **실습 03**: 대화 루프와 웹 화면판이 이력을 쌓는지(덱에서 다루지 않더라도 틀린 말을 피하려면 필요), system 프롬프트의 답 형식 규칙 구조.
6. **실습 01**: `.env` 예시 파일에 항목 설명이 있는지, 이 시점에 데이터 조회용 토큰 칸을 비워 두는지, 검증 실행의 성공 출력, 환경 맞추기에 걸리는 시간.
7. **실습 06**: 원클릭 설치 묶음이 settings까지 써 주는지, 성공 · 실패 때의 첫 화면, `/status`가 사내 배포판에서 동작하는지.
8. **실습 07**: 시작 폴더, 버그 찾기의 대상 파일.
